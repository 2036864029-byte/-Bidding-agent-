# 项目概况相似检索与金额参考 · 执行方案（2026-09-16）

> 目标能力：用户输入/粘贴一段**招标项目概况**（可能含产品需求信息），系统返回**历史相似项目的中标金额参考**（统一万元口径），并附**完整项目信息 + 原始公告链接 + 产品需求明细**，供用户定价参考。
>
> 设计基调：**独立新链路（与 doc_index / public_kb 并列），纯增量，不碰 price_engine 现有 intent/守卫/SQL 构建**。v1 向量单路召回；v2 挂关键字混合召回（复用现有 `RecallPipeline`）。

---

## 1. 数据基础（2026-09-16 实测验证）

数据来自 `bidding` 库（CCGP 2026 新增爬取），四张表关联链完整：

| 表 | 行数 | 关键字段 | 对齐情况 |
|---|---|---|---|
| `announcement` | 802 | `announcement_id`(唯一)、`project_no`、`project_name`、`purchaser_name`、`region_name`、`award_amount`、`publish_time`、`content_text`、**`source_url`** | `content_text` 100% 非空（中位 2660 字，完整中标公告正文含「主要标的信息」）；`award_amount` 100% 有值；`source_url` 802/802 非空，但**语义是「对应公告的具体链接」，实际只有 292 条是真 http 公告页**（见 §1.1） |
| `project` | 755 | `project_no`、`project_name`、`award_amount`、`region_name`、`source_url` | `announcement.project_no` → `project.project_no`（786→755，1:多） |
| `project_product_item` | 1,489 | `announcement_id`、`product_name`、`normalized_product_name`、`brand`、`model`、`quantity`、`unit`、`unit_price`、`total_price` | **100% 关联 announcement，覆盖 673/802（84%）公告** |
| `award` | 817 | `announcement_id`、`supplier_name`、`award_amount`、`award_date` | 726 条有金额（多中标人明细，参考主金额仍用 `announcement.award_amount`） |

**金额分布**（决定参考口径）：724 条 >0；**≤1000 元脏行仅 4 条**；≥1 亿大额基建 6 条；中位 ≈ 1,040 万元。

**结论：802 条带「完整概况 + 中标金额 + 产品明细」的对齐数据，足够支撑前期完整展示。**

### 1.1 source_url 语义与补全（2026-09-16 实测）

**`source_url` 字段语义 = 对应公告的具体网页链接（非官网首页）。** 实测结论：

- **292/802**：真 http 链接，即具体中标公告页：`https://www.ccgp.gov.cn/cggg/{zygg|dfgg}/zbgg/<YYYYMM>/t<ID>.htm`（`zygg`=中央公告 197 条 / `dfgg`=地方公告 95 条，路径段因发布栏目而异）。
- **510/802**：存成了**本地文件路径**（`file://data\raw\ccgp_announcement\<日期>\t<ID>.html`），`crawler_raw_payload.url` 字段同样为空——**爬虫未保存网页 URL，属数据缺口**。
- **可确定性补全**：公告 ID（如 `t20260908_27290030`）就嵌在文件名里，且**全部 802 条 `announcement_id` 唯一**。重构公式：
  ```
  https://www.ccgp.gov.cn/cggg/{zygg|dfgg}/zbgg/<YYYYMM>/t<announcement_id>.htm
  # <YYYYMM> = announcement_id 第 2~7 位（如 202609）
  ```
  `zygg`/`dfgg` 段**用探测判定**（已验证：同 ID 候选 zygg→200 / dfgg→404，三条样本全部命中；ID 数字段有重叠带不可作阈值）。实现为一次性脚本：遍历 file:// 行 → 两个候选 URL 各 GET 一次 → 记 200 者 → 写入 `source_url`（或建 `announcement.source_url_web` 列持久化）。

> 实现顺序上，**先跑补全脚本再建索引**：索引脚本把**补全后的 web 链接**冗余进集合或留待回表读取，前端「查看原文」一律打开可访问的具体公告页。

## 2. 总体架构

```
用户粘贴项目概况
   │  POST /inquiry/reference { text }
   ▼
api/inquiry_reference.py（新模块）
   │  ① embedding（BGE-M3，复用 core/embeddings，隧道 18003）
   ▼
Milvus 集合 project_announcement_semantic（新）
   │  ② 向量 top-K 相似检索 → announcement_id 列表（HNSW, COSINE）
   ▼
MySQL bidding 库
   │  ③ 回表：announcement 主信息（金额/链接/地区/时间）+ project_product_item 产品明细
   ▼
   │  ④ 金额统一万元、相似度排序、产品明细打包
   ▼
{ amount_stats, projects[{...source_url, products[...]}] }
   ▼
前端询价页右栏：ReferenceSummary（金额区间）+ SimilarProjectList（项目卡+原文链接+产品明细折叠）
```

与现有链路的关系：**与 `public_kb_chunked_v2`（法规 RAG）、`doc_index`（上传文档问答）、price_engine 语义召回完全并列**，各自独立集合、互不读写。

## 3. Milvus 集合 schema

**集合名**：`project_announcement_semantic`（写入 `core/vectorstore/namespace.py`，与既有常量并列）。

```python
# core/vectorstore/namespace.py 追加
PROJECT_ANNOUNCEMENT_COLLECTION = "project_announcement_semantic"
```

**schema**（参考 `price_engine/semantic.py::_create_mysql_semantic_collection` 的写法；索引用 HNSW 而非 IVF_FLAT，与 09-08 后全站标准一致）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `announcement_id` | VARCHAR(128) **主键** | 802/802 唯一（已实测），回表键 |
| `project_no` | VARCHAR(128) | 冗余存储，便于检索后快速定位 |
| `region` | VARCHAR(64) | 冗余存储（供可选地域过滤） |
| `text` | VARCHAR(65535) | 实际被向量化的文本（调试/可解释性） |
| `vector` | FLOAT_VECTOR(1024) | BGE-M3 1024 维 |

**索引参数**：`HNSW`，`metric_type=COSINE`，`params={"M": 16, "efConstruction": 200}`。加载后 `load_collection`。

**被向量化的文本构成**（关键设计，决定检索质量）：

```
{project_name}
{产品需求清单：join project_product_item 的 normalized_product_name，逗号拼接，无产品则省略}
{content_text 截断前 ~1800 字}
```

> **为什么截断 1800**：`core/embeddings/bge_m3.py::_SafeEmbeddings` 的 `max_text_chars=2000`，超长会被硬截。中位 2660 字超限——把「项目名称 + 产品清单」放最前（语义最像"产品需求"），正文截取头段（含项目概况/主要标的信息），**最关键的相似信号优先进入向量**。v2 再做正文分块。

## 4. 索引脚本 `scripts/build_announcement_index.py`

复用 `core.rdb.mysql_pool` + `core.embeddings.bge_m3.create_embeddings` + MilvusClient（配置全部走 `Settings`）。

```
用法：
  .venv\Scripts\python.exe scripts/build_announcement_index.py          # 增量 upsert（按 announcement_id 幂等）
  .venv\Scripts\python.exe scripts/build_announcement_index.py --rebuild # 删库重建（schema 变更时）
  .venv\Scripts\python.exe scripts/build_announcement_index.py --dry-run # 只看条数与抽样文本，不写库
```

步骤：
1. `SELECT announcement_id, project_no, project_name, region_name, content_text FROM announcement`。
2. 批量取 `project_product_item.normalized_product_name`（`WHERE announcement_id IN (...)`）拼产品清单。
3. 按 §3 文本构成组句 → 截断 1800 字。
4. 每批 100 条 `embed_documents`（BGE-M3）。
5. 集合不存在 → 建；`--rebuild` → 先 `drop_collection`；否则按 pk 幂等 upsert。
6. 结束打印：索引条数、抽样 2 条文本。

**前置依赖**：Milvus v26 在跑（19531）、模型隧道在跑（18003）、MySQL 在跑（3306）。

## 5. 回表 SQL（`api/inquiry_reference.py` 内）

向量 top-K 拿到 `announcement_id` 列表后，两条 SQL：

```sql
-- ① 主信息（含原文链接）
SELECT announcement_id, project_no, project_name, purchaser_name,
       region_name, award_amount, publish_time, source_url
FROM announcement
WHERE announcement_id IN (%s, %s, ...)
  AND award_amount > %s          -- 金额下限：默认 1000（排除 4 条 ≤1000 元脏行）

-- ② 产品明细（按公告聚合）
SELECT announcement_id, product_name, normalized_product_name, brand,
       model, quantity, unit, unit_price, total_price
FROM project_product_item
WHERE announcement_id IN (%s, %s, ...)
ORDER BY announcement_id, unit_price DESC
```

程序侧按相似度分数对结果排序；`products` 按公告分组挂到对应项目下。金额阈值与可选地域过滤由查询参数传入。

## 6. 端点契约 `POST /inquiry/reference`

**Request**：

```json
{
  "text": "招标项目概况文本……（用户粘贴，>=10 字）",
  "top_k": 10,
  "min_amount_wan": null,
  "region": null
}
```

**Response 200**：

```json
{
  "query": "……",
  "total": 8,
  "amount_stats": {
    "min_wan": 12.50, "median_wan": 860.00,
    "max_wan": 3120.00, "avg_wan": 210.30, "sample_count": 8
  },
  "projects": [
    {
      "announcement_id": "t20260911_27316252",
      "project_no": "XYTDZB-2026TP151-04号",
      "project_name": "和田地区妇幼保健院2026年检验试剂采购项目（包四）",
      "region": "新疆维吾尔自治区",
      "purchaser": "和田地区妇幼保健院",
      "winning_amount_wan": 9.99,
      "winning_date": "2026-09-11",
      "source_url": "https://www.ccgp.gov.cn/……",
      "score": 0.78,
      "products": [
        { "product_name": "ABO血型正反定型及Rh血型检测卡（微柱凝胶法）",
          "model": "5*12卡/盒", "quantity": "1", "unit": "盒", "unit_price_yuan": 31 }
      ]
    }
  ]
}
```

**错误语义**：
- `400`：`text` 为空或 <10 字 → `{"detail": "请提供更完整的项目概况（至少 10 字）"}`。
- `503`：集合未索引/未就绪 → `{"detail": "项目概况知识库未初始化，请先运行 scripts/build_announcement_index.py"}`。
- 其余未捕获异常 → 统一友好降级（沿 `_with_fallback` 模式），不回 500 裸栈。

> `source_url` 返回的是**补全后的具体公告页链接**（§1.1）：292 条取库中原 http 值；510 条取补全脚本探测到的 web 链接。保证前端「查看原文」打开的总是可访问的具体公告页，而非 `file://` 本地路径或官网首页。

**注册方式**：直接在 `api/server.py::create_app` 内 `@app.post("/inquiry/reference")`（与 `/kanban/overview` 同模式），查询逻辑放 `api/inquiry_reference.py`（或并入 `api/modules.py`，按现有结构选择独立文件更清晰）。**不注册进 chat router**——v1 走独立端点，避开聊天路由的 LLM 分类。

## 7. 金额口径（统一万元）

| 金额 | 口径 | 规则 |
|---|---|---|
| `winning_amount_wan` | **万元** | `award_amount(元) / 10000`，round 2 |
| `amount_stats.*_wan` | **万元** | min/median/max/avg 全部万元 |
| `unit_price_yuan` | **元（有意例外）** | 产品单价保留元 + `unit` 字段标注——沿用 Phase 3 既定口径（"inquiry 单价保留元，用万元会变 0.0031，不合理"），字段名即标注单位 |
| 过滤 | — | 默认 `award_amount > 1000`（排除 4 条脏行）；`min_amount_wan` 参数可上调；≥1 亿大额基建 6 条**默认纳入**（中位数不受少数极端影响），如需要可加 `max_amount_wan` |

> 单位字段命名即契约：`_wan` / `_yuan` 后缀明确标注，杜绝复用 `fmtAmountWan` 的混用事故（Phase 3 踩过 1 万倍坑）。

   - 现有 `buildReference(records)` 派生的旧路径保留（对话→报价参考），新路径并行，不互相影响。
7. **测试**：新增 reference 的 mock 渲染 / adapter 映射 / 页面集成测试；`.env.test` 已固定 mock，无需新环境配置。

| 保证 | 依据 |

## 12. 风险与后续（v2）

- **长文本截断**：v1 截 1800 字可能丢正文中段信息 → v2 对 `content_text` 按「主要标的信息」段单独切块索引 + 检索后段落级聚合。
- **纯向量召回局限**：精确型号/品牌（RZ-2201、DS-2CD）向量可能不如 FULLTEXT → v2 挂关键字混合召回（复用 `core.retrieval.RecallPipeline`，阶段短路/熔断现成）。
- **上传文件形态**：v1 支持粘贴文本；上传招标文件 → 复用现有 `doc_index` 文本提取 → 同一 reference 端点，v1.5 补。
- **相似度阈值**：COSINE 0.30 起步（沿用语义召回阈值），上线后按金标校准。
- **语料扩容**：后续 CCGP 增量爬取 → 索引脚本按 pk 幂等增量 upsert 即可。
- **金额口径**：≥1 亿大额项目、≤1000 脏行的处理已有默认值，若演示时发现极端值干扰中位数，加 `max_amount_wan` 参数。
