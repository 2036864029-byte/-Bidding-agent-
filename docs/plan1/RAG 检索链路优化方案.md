# RAG 检索链路优化方案

## （基于 Milvus 2.6 原生分组检索 + 子块打分 + 父块完整返回）

------

## 一、方案核心目标

针对当前链路中「同一父块的多子块挤占 top-K 坑位、上下文碎片化、多样性不足」的核心问题，基于现有技术栈最小化改造，实现三大目标：

1. **解决挤占问题**：从召回层面保证每个父块只占 1 个召回名额，彻底避免同一条答案的碎片占满 top-5；
2. **对齐设计初衷**：实现「细粒度子块负责精准召回、完整父块负责上下文输出」的分层能力；
3. **全场景兼容**：天然兼容独立单块、单子块父块、多子块父块三种形态，无需额外分支判断。

------

## 二、前置数据标准化（新增核心修正点）

### 2.1 核心规则：parent_chunk_id 字段统一规范

**开启 Milvus 分组检索的前提：保证每个独立语义单元自成一组**，仅需更新 1 个标量字段，**无需重新入库、无需重跑 embedding、无需重建向量索引**。

表格

| 块类型                    | parent_chunk_id 取值规则 | 分组效果                                                    |
| ------------------------- | ------------------------ | ----------------------------------------------------------- |
| 有父块的子块              | 正常赋值为对应父块的 ID  | 同父块的所有子块归为同一组，每组仅返回相似度最高的 1 条     |
| 独立块 / 顶级块（无父块） | 赋值为自身的 `chunk_uid` | 每个独立块自身就是一个分组，每组天然只有 1 条，全部正常召回 |

> ❌ 禁止用统一默认值（0、空字符串、null）：所有独立块会被归为同一个组，最终仅返回 1 条，导致独立块召回率崩盘。

### 2.2 存量数据修复

执行一次 Milvus 标量字段批量更新，分钟级完成，不触碰向量数据：

```
# 伪代码：将所有默认值的独立块，parent_chunk_id 替换为自身 chunk_uid
# 1. 查询出所有 parent_chunk_id 为默认值的记录
default_chunks = milvus_client.query(
    collection_name="your_collection",
    expr="parent_chunk_id == 0",  # 替换为你的实际默认值，如 "" 或 null
    output_fields=["chunk_uid", "parent_chunk_id"]
)

# 2. 批量更新为自身 chunk_uid
update_data = [
    {"chunk_uid": item["chunk_uid"], "parent_chunk_id": item["chunk_uid"]}
    for item in default_chunks
]
milvus_client.upsert(collection_name="your_collection", data=update_data)
```

### 2.3 新增数据入库逻辑修正

在分块写入代码中新增 1 行规则，从源头保证字段一致性：

- 若为子块：`parent_chunk_id = 父块ID`（保持原有逻辑不变）
- 若为独立块 / 顶级块：`parent_chunk_id = chunk_uid`（不再设为默认值）

## 三、改造后完整链路总览

```
用户Query
    ↓
┌─ 稠密检索（Dense）───────────────────────────┐
│  Milvus 2.6 原生按 parent_chunk_id 分组检索  │
│  每组返回相似度最高1条子块，共召回30条     │
└───────────────────────────────────────────────┘
    ↓
┌─ 稀疏检索（BM25）─────────────────────────────┐
│  关键词召回30条子块 → 按 parent_chunk_id 去重│
│  每组保留得分最高1条，输出30条不同父块     │
└───────────────────────────────────────────────┘
    ↓
┌─ RRF 融合层 ──────────────────────────────────┐
│  两路结果按 RRF(k=60) 公式融合 → 取前30条   │
│  输出：30条来自不同父块的子块候选           │
└───────────────────────────────────────────────┘
    ↓
┌─ Rerank 重排层 ───────────────────────────────┐
│  bge-reranker 逐条子块粒度打分排序           │
│  输出：按相关性排序的top-K子块（如top-5）    │
└───────────────────────────────────────────────┘
    ↓
┌─ 父块补全拼接层（新增核心）───────────────────┐
│  1. 提取所有top-K子块的parent_chunk_id       │
│  2. 批量查询对应父块的全部子块               │
│  3. 按序号拼接为完整父块，去重冗余前缀       │
│  4. 输出：K个完整语义块 → 送入LLM上下文      │
└───────────────────────────────────────────────┘
```

**核心原则**：**打分永远用子块（保证精准），输出最终用父块（保证完整）**；召回层去重解决挤占问题，后处理拼接解决上下文问题。

## 四、分模块详细改造方案

### 4.1 稠密向量检索侧：Milvus 2.6 原生分组去重

**改造点**：仅在 Milvus 搜索接口新增 2 个参数，零业务代码开发；基于前置标准化的数据，天然兼容所有块类型。

#### 具体配置

在原有 `search` 请求参数中新增：

表格

| 参数名           | 取值                | 作用                                            |
| ---------------- | ------------------- | ----------------------------------------------- |
| `group_by_field` | `"parent_chunk_id"` | 指定按父块 ID 字段分组                          |
| `group_size`     | `1`                 | 每组仅返回相似度最高的 1 条子块                 |
| `limit`          | `30`                | 返回 30 个**分组**（即 30 个不同父块 / 独立块） |

#### 兼容说明

数据标准化后，独立块、单子块父块、多子块父块走完全相同的分组逻辑，无需任何 `if` 分支判断，Milvus 原生自动适配。

#### 优势

- 全量数据维度分组，而非对返回结果裁剪，召回精度高于业务层后处理去重；
- 内核级执行，性能远高于 Python 层循环去重；
- 代码改动量极小，仅参数级调整。

------

### 4.2 稀疏关键词检索侧：业务层父级去重

**改造点**：BM25 召回完成后、进入融合前，增加一步父级去重逻辑。

#### 处理逻辑

1. BM25 按原有逻辑召回 top-30 子块，保留每条的得分和 `parent_chunk_id`；
2. 按 `parent_chunk_id` 分组，每组只保留**关键词得分最高的 1 条子块**；
3. 不足 30 条时，按排名从后续候选中补位，最终输出 30 条来自不同父块的子块。

> 若 BM25 基于 Milvus 标量索引实现，可直接复用 4.1 的 `group_by_field` 参数，和稠密侧逻辑完全一致，无需额外代码。

------

### 4.3 RRF 融合层：无改造

两路召回输出均已保证「每条来自不同父块」，RRF 融合逻辑完全保持不变：

- 融合公式：`score = Σ 1 / (k + rank)`，其中 `k=60`
- 融合后取前 30 条作为候选集
- 输出候选集天然无同父子块重复

------

### 4.4 Rerank 重排层：无改造

**保持子块粒度打分，不做任何改动**，这是保证排序公平性的核心：

1. 所有候选统一以子块粒度输入 reranker，逐条计算相关性得分；
2. 按得分降序排序，取 top-K（如 top-5）；
3. 打分阶段完全不涉及拼接、不涉及长度差异，彻底规避长度带来的评分偏差。

------

### 4.5 父块补全拼接层（核心新增模块）

**唯一需要新增业务代码的模块**，输入为 rerank 后的 top-K 子块列表，输出为对应数量的完整父块文本。

#### 执行步骤

1. **ID 提取**：从 top-K 子块中提取所有不重复的 `parent_chunk_id`；
2. **批量查全量**：用该 ID 列表去 Milvus 批量查询 `parent_chunk_id` 命中的所有子块；
3. **分组排序**：按 `parent_chunk_id` 分组，每组内按 `sequence_in_parent` 升序排列；
4. **文本拼接与清洗**：
   - 单条组（独立块 / 单子块父块）：直接保留原文，不做处理；
   - 多条组（多子块父块）：按顺序拼接文本，同时移除重复的统一前缀（如 QA 类的「问：XXX？\n\n 答：」），仅保留首个前缀；
5. **长度熔断（可选）**：设置父块最大长度阈值（建议 2000 字符），超过则只保留得分最高的子块 + 前后各 1 块上下文，避免超长文本占用 LLM 上下文；
6. **结果输出**：保持原有的子块排名顺序，输出 K 个完整语义块。

#### 核心逻辑伪代码（Python）

```
from collections import defaultdict

def assemble_parent_chunks(top_k_chunks: list[dict], milvus_client) -> list[str]:
    # 1. 提取所有父块ID（去重）
    parent_ids = list({chunk["parent_chunk_id"] for chunk in top_k_chunks})
    
    # 2. 批量查询对应父块的全部子块
    all_children = milvus_client.query(
        collection_name="your_collection",
        expr=f'parent_chunk_id in {parent_ids}',
        output_fields=["chunk_uid", "parent_chunk_id", "sequence_in_parent", "text"]
    )
    
    # 3. 按父块分组 + 按序号升序排序
    parent_groups = defaultdict(list)
    for child in all_children:
        parent_groups[child["parent_chunk_id"]].append(child)
    for pid in parent_groups:
        parent_groups[pid].sort(key=lambda x: x["sequence_in_parent"])
    
    # 4. 按原top-K顺序输出，保证排名不变
    result = []
    prefix_mark = "问："  # QA类统一前缀，按需调整
    
    for chunk in top_k_chunks:
        pid = chunk["parent_chunk_id"]
        children = parent_groups[pid]
        
        # 单条：独立块/单子块父块，直接返回
        if len(children) == 1:
            result.append(children[0]["text"])
            continue
        
        # 多条：拼接 + 去重问题前缀
        texts = []
        prefix_removed = False
        for c in children:
            text = c["text"]
            if not prefix_removed and text.startswith(prefix_mark):
                texts.append(text)
                prefix_removed = True
            elif prefix_removed and text.startswith(prefix_mark):
                # 跳过重复前缀，仅保留正文
                split_idx = text.find("\n\n")
                texts.append(text[split_idx+2:] if split_idx != -1 else text)
            else:
                texts.append(text)
        
        full_text = "\n".join(texts)
        result.append(full_text)
    
    return result
```

## 五、边界场景兼容处理

表格

| 场景                               | 处理逻辑                                                     | 兼容性   |
| ---------------------------------- | ------------------------------------------------------------ | -------- |
| 独立单块（无父块）                 | `parent_chunk_id = 自身chunk_uid`，分组后单条直接返回，拼接层透传 | 天然兼容 |
| 父块下只有 1 个子块                | 分组后单条，不触发拼接                                       | 天然兼容 |
| 子块序号不连续（缺号）             | 按现有序号顺序拼接，缺号跳过并打日志，不强行补全             | 容错处理 |
| 父块全文超长                       | 触发长度熔断，保留核心片段，避免撑爆 LLM 上下文              | 可控风险 |
| 非 QA 类型块（法律条文、书籍章节） | 无统一前缀，直接按序拼接，不做前缀去重                       | 通用兼容 |
