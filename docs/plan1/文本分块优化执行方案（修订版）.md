# 文本分块优化执行方案（修订版）

> 修订依据（2026-09-08 审查结论）：
> 上一版 TypedChunker 只按"类型原子标题"切分（law 只在 `第X条`、qa 只在问项），
> 其余标题（法名/章名）仅压栈当元数据，导致法规全书里 55 部法的 `# 法名` 一级标题
> 全被并进一个 37.6 万字符的块。**根因是切分粒度设计错误，不是数据、不是预处理、
> 不是层级被破坏**（大块内部 55 个一级标题完好，即为证据）。
>
> 修订核心：**先按所有标题层级切分，再按类型做原子/超限细分**，超大块在源头消失。

---

## 一、分块主流程（两层切分）

### 前置（必须，防内容丢失）：类型化"标题内联正文"提取

cleaned_v1 的法规是 `## 第一条  正文` 内联形态（实测 69/69 条正文都在标题行里）。
**切分前必须先做内联提取**（law/law_compilation 拆 `第X条 正文`，qa 拆问题行），
否则"标题进元数据"后正文会全部丢失。这一步是**必需步骤**，不是可选清洗。
（QA/book 输入已是 Phase A 产物，幂等无害。）

### 第 1 层：按所有标题层级切分（结构切分）

- **每个 Markdown 标题（任意 `#` 级）都是一个切分点**，不做类型区分。
- 标题行 → 标题栈（元数据，最终拼成 `hierarchy_path`）；
- **块的"自己的标题行"保留在 chunk 内容开头**（law 条号 / qa 问题 / book 小节号，
  自包含且可溯源）；**祖先标题只进元数据**；
- 块内容 = 自己的标题行 + 两标题之间的正文行；
- 两个标题之间无正文 → 自然不产生块（**没有"产生块再丢弃"的逻辑，内容零丢失**）。

效果（以法规全书为例）：
```
# 中华人民共和国招标投标法        → 块A（沿革正文）
## 第一章 总 则                    → 无正文，不产生块（章名进元数据）
#### 第一条【立法目的】            → 块B（自己的标题行 + 本条正文）
#### 第二条【适用范围】            → 块C
# 中华人民共和国政府采购法         → 块D（新法规名 = 新切分点）…
```
55 部法、政策各自成块，**39 万字符超大块在源头消失**（实测最大块 37.6 万 → 切分后最大 ≤ 单部法规长度）。

### 第 2 层：块内细分（超限才触发）

对第 1 层产生的每个块：

| 情形 | 处理 |
| --- | --- |
| 块正文 ≤ 类型阈值 | 直接 1 个 chunk |
| 块正文 > 类型阈值 | 按「类型化次级标题 → 段落 → 句子」逐级切分，每段 1 个 chunk |

次级标题与类型的关系（配置表）：
- law / law_compilation：`#### （一）/一、` 款项；
- qa：答案内段落；
- book：`#### 一、/（一）` 小节。

所有细分出的 chunk **共享同一 `hierarchy_path`**，并带块内顺序号 `sequence_in_parent`。

## 二、类型分流（review 结论 + 改进）

### 现状实测（全部真实数据）
- `cleaned_v1/markdown` 349 部 → **全部 law**（按目录，鲁棒）；
- `handoff_v3/clean` 3 本 → **qa / book_practical / law_compilation**（按文件名关键词，命中）。

### 改进：显式配置表 + 三层判定，去掉魔法关键词

```python
TYPE_ROUTING = [
    # (匹配条件, doc_type)
    (path_contains("cleaned_v1/markdown"),              "law"),
    (filename_has(("1200问","问答","答疑","问题")),      "qa"),
    (filename_has(("实务","手册","指南","教程","解读")), "book_practical"),
    (filename_has(("法规全书","汇编")),                   "law_compilation"),
    (path_contains("handoff"),                           "book_practical"),  # 兜底
]
```

判定顺序：**目录规则 → 文件名关键词 → 目录兜底 → 显式 `--doc-type` 覆盖**。
未知来源目录 → 默认 `book_practical` 风格（按所有标题切分，不依赖关键词，切分正确性不受影响）。

### 分流与切分解耦
doc_type 只影响三件事，不影响"按所有标题切分"这一主流程：
1. 原子块阈值（law 700 / qa 900 / book 1000）；
2. 超限块的次级标题切分规则；
3. 类型专属元数据（law→`article_number`、qa→`question`）。

## 三、元数据设计（不变）

| 字段 | 生成规则 |
| --- | --- |
| `chunk_uid` | `ck-md5(doc_name\|chapter\|chunk_index\|text)`，幂等去重键 |
| `doc_id` / `doc_name` / `doc_type` | 分流 + 文件名 |
| `chapter` / `hierarchy_path` | 标题栈全路径（含法名/章名/条号） |
| `chunk_index` | 文档内全局递增顺序号 |
| `article_number` | law 系列：本条条号 |
| `question` | qa：完整问题文本 |
| `chunk_type` / `parent_chunk_id` / `sequence_in_parent` | 二期父子块预留 |
| `effective_date` / `status` / `embedding_model` / `schema_version` / `source_format` | 同前 |

### 父子块预留（一期规则）
- 未超限块：`chunk_type=atom`，`parent_chunk_id=""`，`sequence_in_parent=0`；
- 超限块切成 N 段：`chunk_type=child`，`sequence_in_parent=1..N`，`parent_chunk_id` 指向**合成父标识** `{doc_id}|sec_{块序号}`；
- **一期不落整块 parent 行**（杜绝超长行），二期启用时再决定父块是否入库。

---

## 四、类型特殊处理

### QA（1200 问，实测 797 个问项）
- 块内容 = **问题文本 + 答案**（检索时模型直接看到问题，不依赖元数据）；
- `question` 元数据同时记录完整问题；
- 超长答案：答案子块前缀完整问题（`问：xxx？\n\n...`）。

### law / law_compilation
- 条号既在 `hierarchy_path`，也落 `article_number`；
- 条标题内联正文：输入已是 Phase A 清洗产物（已拆分），chunker 侧不再重复清洗。

## 五、代码结构（收敛，目标 ≤ ~200 行）

```
typed_chunker.py
├─ TYPE_CONFIG          # 分流表 + 每类型 {threshold, sub_split_re, special}
├─ HeadingSplitter      # 通用：所有标题切分 + 标题栈元数据
├─ OversizeSplitter     # 超限：次级标题 → 段落 → 句子（复用 _split_by_sentence）
├─ TypedChunker.chunk() # 编排：HeadingSplitter → OversizeSplitter → 元数据/uid
└─ detect_doc_type*     # 配置表驱动分流
```

不再叠加补丁；现有 400+ 行收敛为配置驱动。
