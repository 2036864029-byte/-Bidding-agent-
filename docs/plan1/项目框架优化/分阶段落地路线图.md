先给你一个笃定的核心结论：**先补 20% 的核心架构短板，再叠加你想要的多 Agent、Deep Agent、质量管控等功能模块**。

既不能在地基有结构性缺陷的情况下硬堆功能（最后会变成技术债务泥沼，改不动也调不动），也不用等架构 “完美” 了再做业务（会错过迭代窗口，过度设计）。最优路径是：用最短时间把 P0 级架构风险补上，让框架具备 “可安全叠加功能” 的基础，然后快速迭代业务能力。

## 一、分阶段落地路线图（完全匹配你的现有代码）

### 第一阶段：架构筑基（2-3 周，解决 P0 级结构性风险）

**目标**：让主框架具备可扩展、可调试、可排错的基础，加新功能不会越写越乱 **核心原则**：只改骨架，不动业务逻辑（RAG、价格引擎全部保持原样）

#### 重点做 4 件事：

1. **梳理编排分层边界，统一状态模型**
   - 明确三层架构契约，解决现在`agent/`与`orchestration/`职责重叠的问题：
     - 路由调度层：统一由主控 Agent 负责（后续从`router.py`升级）
     - 执行层：单节点 / 单 Agent（领域内流程）
     - 能力层：`price_engine`、`public_kb`等领域引擎，只暴露标准接口 / 工具
   - 重构`AgentState`：补齐会话元数据（会话 ID、用户 ID、渠道、时间戳）、任务生命周期、链路追踪 ID，作为全链路唯一状态载体
   - 收敛检查点机制：统一由`checkpointer.py`管理状态持久化，避免两层各管一套
2. **建立统一错误处理与容错体系**
   - 定义全局错误码（系统错误 / 业务错误 / 模型错误分级）
   - 实现全局异常处理器，统一错误返回格式
   - 封装通用重试、熔断、降级逻辑，沉淀到 core 层，每个节点可配置使用
3. **铺最小可用可观测性底座**
   - 结构化日志 + `request_id`全链路透传，从 API 入口贯穿到节点、LLM、向量库
   - 关键路径埋点：路由耗时、节点执行耗时、LLM 调用耗时 & Token 数、检索耗时
   - 不用一上来就上 OpenTelemetry 全套，先解决 “能排查问题” 的核心诉求
4. **补齐基础安全管控**
   - API 层增加鉴权（API Key）
   - 工具调用增加沙箱校验，尤其是价格引擎的 SQL 构造逻辑，增加注入防护
   - 输入输出敏感词校验收敛到护栏层

**准出标准**：新增一个业务节点 / Agent，不需要修改核心编排代码；线上出问题能通过日志定位到具体环节和错误原因。

### 第二阶段：多 Agent 体系落地（3-4 周，叠加你想要的全部功能）

**目标**：落地主从架构、深浅分流、质量管控、全量工具化 **基于现有组件改造，90% 复用现有代码，不需要推倒重来**

#### 重点做 4 件事：

1. **主控 Agent（Supervisor）：由`router.py`升级而来**
   - 核心职责：意图识别 → 任务分流 → 链路调度 → 结果汇总
   - 双轨分流逻辑：
     - 简单 / 明确意图（价格查询、单文档问答）→ 直达对应业务节点 → 快速返回
     - 复杂 / 模糊 / 多步意图（多源对比、分析推理、长尾问题）→ 分发到 Deep Agent → 自主规划执行
2. **Deep Agent：由`tool_agent.py`升级而来**
   - 内置 **Plan-and-Solve 模式**：先生成执行计划，再按计划调用工具执行
   - 所有领域能力全部封装成标准工具注入：价格查询、知识库检索、供应商查询等
   - 执行过程保留 ReAct 循环，支持动态调整计划
3. **质量管控护栏：由`guardrail_hooks.py`扩展升级**
   - 前置校验（路由前执行）：敏感词、超长文本、非法意图、业务范围校验
   - 后置校验（每个执行单元输出后执行）：
     - 规则类（毫秒级）：输出格式合规、必填字段齐全、引用格式正确
     - 轻量模型类：事实一致性、回答相关性、数据可追溯性
   - **不达标处理机制**：简单问题打回重跑，复杂问题降级输出或触发人工兜底
   - 耗时控制：核心路径只跑规则校验，耗时增加 < 10%；深度校验异步执行，不阻塞主流程
4. **领域能力工具化改造**
   - 保留`agent/nodes/`下的节点直出快速路径
   - 同时将`price_engine`、`public_kb`等封装成标准 LangChain 工具，供 Deep Agent 调用
   - 两套路径复用同一套底层能力，避免逻辑分叉

**准出标准**：简单问题毫秒级返回，复杂问题自主规划执行；所有输出经过统一质量校验。

### 第三阶段：体系完善与优化（持续迭代）

**目标**：可量化、可优化、可运营

1. 搭建完整评测体系：基于你现有的金标集，实现自动化评测（路由准确率、回答准确率、引用正确率、价格命中率）
2. 引入**Reflection 反思模式**：后置校验不通过时，触发 Deep Agent 反思问题、修正答案
3. 性能优化：多级缓存（语义缓存、检索缓存、LLM 结果缓存）、长耗时任务异步化、水平扩展能力
