> **本修订版合并两份输入**：

> ②《docs/前端接口清单.md》（2026-09-13，从代码提取的权威契约）——**对话主模块与后端接线以此为基准**。

## 0. 结论速览

- **架构 = Domain Model + Adapter**（规划方案 §1.1）：UI 只依赖前端自定的领域接口，`src/adapters/` 统一转换；未来后端上线只改适配层，UI 0~少量改动。**与「契约先行」天然一致，当前数据不对也不阻塞。**
- **布局 = 上/中/下三段式落地页**（用户确认）：上 = 品牌区「招小智」；中 = 三模块入口卡；下 = **居中主对话窗口（随对话自适应扩大浮窗）**。**商机看板点击跳转新页面**；智能询价/供应商点击**跳转页面 或 右侧大 Drawer 浮窗**（二选一，模块组件复用、决策可后置）。
- **技术栈（定版）**：Vite 6 + React 19 + TS 5 + Tailwind v4 + **Shadcn UI** + **Framer Motion** + **Recharts** + react-router + Zustand + react-markdown + `@microsoft/fetch-event-source`；视觉按 **Hallmark 规范**。
- **前端整体放 `frontend/` 独立目录（前后端分离）**：独立 package，仅经 HTTP/SSE 与后端通信；开发期 Vite 代理 `/api → 127.0.0.1:8000`，生产走同域反代。
- **三模块 = mock 先行；对话主模块 = 接真实后端（现在就能用）**。

## 1. 方案对比与合并决策（规划方案 vs 本会话前版 vs 代码现状）

| 维度 | 规划方案 | 本会话前版（09-14 首版） | **合并决策** |
|---|---|---|---|
| 技术栈 | Vite+Tailwind+Shadcn+Framer+Recharts | Vite+Tailwind+Zustand+react-markdown（无 Shadcn/Framer/Recharts） | **采纳规划方案**，补 react-markdown/fetch-event-source/Zustand（对话渲染与 SSE 必需） |
| 布局 | 全屏工作台 + 双栏（左导航 + 中央看板/对话），模块独立页面 | 单页 hub（中间三卡 + 底部对话框） | **回归用户原始 上/中/下 三段式**（上品牌/中模块卡/下对话浮窗）；模块内容与视觉仍取规划方案 |
| 三模块形态 | 三个独立页面（看板/询价/供应商），Mock 先行 | 「入口卡」为主，独立页面挂 Phase 6 | **采纳规划方案**：三页面 + Mock + Adapter |
| 对话模块 | SSE 流式 + CoT 折叠 + 联动操作卡（未定义后端契约） | 以接口清单 7 种 reply_type 精确接线 | **以接口清单为准**（规划方案未落地契约处，由本方案补齐） |
| 数据接入 | Mock-First 适配器（未来换 API） | 契约先行（要求层/字段层） | **天然一致**：Domain+Adapter 就是契约先行的落地 |
| 目录 | pages/kanban,inquiry,supplier,chat + adapters/ mock/ services/ | api/ renderers/ store/ | **合并**：规划方案树 + 本方案的 store/（会话/流式状态）与 renderers（reply_type 分发） |
| 阶段顺序 | 基座→契约/mock→三模块 UI→对话控制台 | 对话闭环在前 | **采纳规划方案顺序**（视觉基座 → 契约 → 三模块 → 对话控制台），对话是唯一接真后端阶段 |

**对本会话前版的 4 处改进（源自规划方案）**：
1. 布局：单页 hub → **上/中/下三段式落地页 + 路由多页**（react-router），模块卡片跳独立页或浮窗。
2. 三模块：入口卡 → **真页面 + Mock 高保真**（热力图/占比/走势、对比表+Drawer、网格卡+雷达+筛选）。
3. 视觉：朴素 → **Hallmark 规范 + Shadcn + Framer Motion 微交互**。
4. 数据层：API client → **Domain + Adapter 双契约**（types/ 领域契约 + adapters/ 转换层 + services/ 切换 Mock↔API）。

**对规划方案的 4 处代码现状补充/修正**：
1. **「联动操作卡」后端不产信号**——`/chat` 只返回 `reply_type/data`；"从 Agent 结果一键跳业务模块"是**前端自建**能力（在 `price_records` 等结果上渲染"在询价模块查看详情"按钮），别指望后端给。
2. **商机看板热力/占比/走势、供应商雷达/评分、询价偏离度——当前 API 与数据都没有**，只能 Mock（适配器已隔离）；未来需**新增只读端点**（§5），且走势/热力维度须在**数据入库前定死**（§5.3 清单）。
3. **CoT 折叠面板只对 `deep_agent` 有真数据**（`data.trace.plan/steps/reflection`）；`kb_answer`/`chat` 等无 trace，按 `reply_type` 显示/隐藏，别默认所有回答都有思维链。
4. **「询价单/对比明细」是未来域模型**——当前 `/chat` 的 `price_records` 返回的是"中标记录表"，不是规划方案里的 `InquirySummary`（DRAFT/IN_PROGRESS/COMPLETED 询价单）。询价页的询价单结构先按领域契约 mock，未来由询价业务提供。

## 2. 技术栈（定版）

| 层 | 选型 | 用途 / 理由 |
|---|---|---|
| 构建 | **Vite 6** | 快、TS 一等公民 |
| 框架 | **React 19 + TypeScript 5** | 用户已定 React |
| 样式 | **Tailwind CSS v4** + **Shadcn UI** | 组件基座 + 主题 token；Hallmark 视觉规范注入主题文件 |
| 动画 | **Framer Motion** | 卡片悬浮、Drawer 平滑滑出、图表动量过渡 |
| 图表 | **Recharts** | 热力图（自绘或用 HeatmapCell）、占比图、时间线走势、雷达图（供应商） |
| 路由 | **react-router** | 双栏多页：/chat /inquiry /kanban /supplier |
| 状态 | **Zustand** | session_id / files / 消息流式状态 |
| 渲染 | **react-markdown + remark-gfm** | 回答 markdown + `【来源N】` 引用链接化 |
| 流式 | **@microsoft/fetch-event-source** | SSE（`EventSource` 不支持 POST） |
| 测试 | **Vitest + @testing-library/react** | 适配器/渲染器单测（真实响应 fixture） |
| 视觉 | **Hallmark 规范**（实现时走 `/hallmark` 技能；若环境无该技能则按其原则落地：大圆角 `rounded-2xl/3xl`、开阔留白、非沉闷政务风） | 全局视觉 token |
| 图表规范 | **dataviz 技能**（写任何图表组件前加载） | 配色/可访问性/图例一致 |

> Node ≥ 20。前端整体在仓库根 `frontend/` 独立目录（前后端分离）。

## 3. 目录结构（`frontend/` 独立包，前后端分离）

```
frontend/
├── index.html
├── vite.config.ts              # dev proxy: /api → http://127.0.0.1:8000
├── package.json
└── src/
    ├── main.tsx  /  App.tsx    # 路由
    ├── assets/                 # Logo, SVG, 图标
    ├── styles/                 # Tailwind 主题 + Hallmark 视觉 token
    ├── components/
    │   ├── ui/                 # Shadcn: Button, Dialog, Drawer, Badge, Table…
    │   ├── common/             # GlassCard, MetricCard, EmptyState, Header, AgentLoading
    │   └── layout/             # LandingLayout(上/中/下), ModulePageLayout(模块页+返回首页)
    ├── pages/
    │   ├── chat/               # 对话控制台（首页，SSE 流式 + reply_type 渲染 + 上传）
    │   ├── kanban/             # 商机看板（漏斗指标栏 + 热力/占比/走势 + 空态注入 Mock）
    │   ├── inquiry/            # 智能询价（对话式需求描述 + 对比表 + 偏离高亮 + Drawer）
    │   └── supplier/           # 供应商全景（多维筛选 + 网格卡 + 雷达 + 详情 Modal）
    ├── types/                  # 前端领域契约（chat/kanban/inquiry/supplier）
    ├── mock/                   # Mock 数据（mockKanban/Inquiry/Supplier）
    ├── adapters/               # 原始数据 → Domain Model（kanban/inquiry/supplier）
    ├── services/
    │   ├── api.ts              # Mock ↔ API 切换控制（数据源开关，唯一开关点）
    │   └── backend.ts          # 真实后端 HTTP/SSE 客户端（chat/files，按接口清单）
    ├── store/                  # session / files / messages 流式状态（Zustand）
    └── lib/                    # cn(clsx/twMerge)、markdown、errors(error_code 映射)
```

> 关键约束：**页面组件只 import `services/api.ts` 与 `types/`，禁止直接碰后端字段**——适配层把后端原始字段映射成领域模型，这是未来换数据的唯一接缝。

## 4. 页面与版面设计

### 4.1 全局 Layout（上 / 中 / 下 三段式落地页 + 模块独立页）

> **2026-09-14 修订**：落地页已按《docs/plan1/主页面优化执行方案_20260914.md》重构为四层形态（吸顶导航 → 介绍带 → 模块卡 → 渐变输入条）+ 发送后聚焦浮窗（× 收起、会话可恢复）。下文为原始规划，落地页以执行方案为准；对话浮窗状态机见 `frontend/src/store/chat-window.ts`。

**落地页（首页 = 对话 + 模块入口）**：

```
┌────────────────────────────────────────────────┐
│ 上：品牌区「招小智」（点击回首页）                │
├────────────────────────────────────────────────┤
│ 中：三模块入口卡                                │
│   ┌───────────┐ ┌───────────┐ ┌───────────┐    │
│   │ 💰 智能询价 │ │ 🏢 供应商  │ │ 📊 商机看板 │    │
│   │ 询价 / 比价 │ │ 供应商全景 │ │ 热力 / 走势 │    │
│   └───────────┘ └───────────┘ └───────────┘    │
├────────────────────────────────────────────────┤
│ 下：主对话窗口（居中，随对话自适应扩大浮窗）        │
│   ┌──────────────────────────────────────────┐  │
│   │  …消息…                                   │  │
│   │  [＋上传] [输入…] [发送]                   │  │
│   └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

**模块访问方式（决策可后置——组件复用，只差挂载点）**：

| 模块 | 推荐 | 备选 | 说明 |
|---|---|---|---|
| 商机看板 | **跳转新页面 `/kanban`** | — | 图表多（热力/占比/走势），独立页展示（用户确认） |
| 智能询价 | 跳转 `/inquiry` | 右侧**大 Drawer 浮窗** | 含对话区 + 对比表 + 调价抽屉，内容重；Drawer 取大尺寸，不用小弹窗 |
| 供应商 | 跳转 `/supplier` | 右侧**大 Drawer 浮窗** | 筛选 + 网格卡 + 雷达 + 详情弹窗，内容重；同上 |

> **实现要点**：每个模块封装为独立组件（如 `pages/inquiry/InquiryModule.tsx`），**挂到页面路由或 Drawer 只差一个挂载点**——"弹小窗 vs 跳转"不影响模块实现，决策可随时改。模块页顶部提供「返回首页」；点品牌「招小智」也可回首页。

**主对话窗口自适应扩大浮窗（下版面）**：
- **形态**：底部居中浮窗卡片，大圆角 + 阴影；高度/宽度过渡用 Framer Motion。
- **自适应**：初始为紧凑「引导卡」（问候语 + 3 个示例问题）；首条消息后按内容高度扩展，**封顶**（`max-height ≈ 70vh`、`max-width ≈ 56rem`），超限后窗内滚动。
- **宽度注意**：`price_records` 渲染**表格**、引用卡片与文件 chips 占横向空间——浮窗最大宽度不能太窄（约 56rem 基准），窄屏时表格窗内横向滚动。
- **不遮挡**：扩展在「下版面」区域内进行，中区模块卡保持可见；必要时浮窗可放大至覆盖全高（用户可选）。

### 4.2 主对话窗口（chat，下版面浮窗）—— **接真实后端**

- 位置：**下版面居中浮窗**，随对话自适应扩大（§4.1）；三模块入口卡在**中版面**（§4.1）。
- 消息列表：悬浮式双气泡，**按 `reply_type` 分发渲染**（注册表）：
  - `kb_answer`：markdown + `【来源N】` 引用展开（`citations[]`）
  - `price_records`：中标记录**表格**（`data.records/tables`）+ "在询价模块查看详情"联动按钮（前端自建）
  - `doc_qa`：正文 + 来源列表 + **显式展示 `data.retrieval.notes` 兜底提示**
  - `deep_agent`：正文 + **CoT 折叠面板**（`data.trace.plan/steps/reflection`，仅此类型有真数据）+ `steps[].sources`
  - `chat`/`safety`/`fallback`：纯文本/安全提示/降级文案
- 底部：输入框 + **＋ 上传**（异步 + 轮询 + 文件 chips）+ 发送/停止。
- **慢路径契约**：agent 路径 9~15s、前 5~10s 无 token → `AgentLoading` 占位；超时 `/chat ≥ 60s`、`/chat/stream ≥ 120s`；**别按 30s 掐**。

### 4.3 商机看板（kanban）—— **Mock 先行**

- 顶部：**漏斗指标栏**（地区 / 行业 / 产品筛选 + 汇总指标卡）。
- 中央可视化（独立页放得开）：① 各地区**热力图** ② 各行业招投标项目**占比图** ③ 按筛选的行业/产品**时间线走势图**。
- 空态：渐变光晕空态插图 + **一键注入 Mock 数据**（`mockKanban`）。
- 数据：现在 **Mock + Adapter**；未来 = 新增只读端点（热力/占比/走势需聚合，见 §5）。

### 4.4 智能询价（inquiry）—— **对话式 + Mock 对比**

- 左侧：**对话式需求描述区**——用户用语言/文件/图片描述需求（图片走现有上传+OCR，真能力），触发 agent 调双库查历史中标金额给价格参考（**接真实 `/chat` 的 `price_inquiry` 路由**）。
- 右侧：**价格对比表 + 调价 Drawer**——多方供应商横向对比；**偏离度高亮**（超预算阈值 → 荧光红/橙 Badge）。
- 数据：对话区现在就能接真 `price_records`；"询价单/对比明细"（`InquirySummary`）是未来域模型，先用 `mockInquiry` + `inquiryAdapter`。

### 4.5 供应商全景管理（supplier）—— **Mock 先行**

- 顶部：**多维多选筛选器**（资质 / 历史合作评分 / 主营类别 / 地区，Tag 组无刷新筛选）。
- 中部：**网格化供应商卡片**——核心履约能力、**雷达图**评分、风险预警标签。
- 详情 **Modal**：参与投标成功率、中标历史价格分布。
- 数据：现在 Mock；未来 read 端点 + 评分口径定义（评分是前端算还是后端给需定，见 §5/§8）。

## 5. 数据契约与适配层（契约先行，数据不对也能做）

### 5.1 架构原则（采用规划方案 §1.1/§4）

```
UI 视图层 ── 只依赖 Domain Interface（types/） ── 从不碰后端原始字段
       ▲                                          ▲
       │                                          │
   services/api.ts（Mock↔API 唯一开关）        adapters/（原始数据 → Domain Model）
```

> 领域契约示例沿用规划方案 §4.1 的 `InquiryItem`/`InquirySummary`；适配器示例沿用 §4.2 的宽容映射（`q.price || q.unitPrice`）。

### 5.2 要求层 vs 字段层（数据不对时怎么定契约）

- **现在能定**：领域契约（`types/`）+ 维度要求清单 + read 端点形态——不依赖最终数据内容。
- **要等新数据源**：字段级映射（适配器里 `raw.xxx` 的键名）——等新表结构定了再填，`adapters/` 是唯一改动处。

### 5.3 新数据维度要求清单（待用户确认/填空，先于数据入库）

| 维度 | 要确认的问题 | 建议默认 |
|---|---|---|
| 时间 | 走势图粒度：天/月/季度？各模块时间字段（成交/发布/处罚日期…） | 月粒度；保留 `date` |
| 地区 | 热力图地域维度按省/市？地区字段规范值 | 省级；规范化编码 |
| 类别 | 商机按项目类别/行业聚合？口径 | 项目类别 |
| 金额 | 中标/预算金额口径、单位（元/万元）、0 与缺失区分 | 元；`null`=缺失、`0`=零元 |
| 唯一性 | 项目/企业稳定唯一键（去重/更新） | 项目编号、企业信用代码 |
| 状态 | 商机是否需要状态（进行中/已截止）支撑「看板」 | 无则按静态数据 |
| **评分** | 供应商评分/雷达图的评分来源：前端算 or 后端给？口径？ | 待定（见 §8） |

## 7. 可执行计划（合并版）

## 8. 风险与决策点

| 项 | 等级 | 说明 / 应对 |
|---|---|---|
| 三模块 Mock 与未来真数据可能差很大 | 🟡 | 适配器隔离 + 维度清单 §5.3 先定形状；换数据只改 adapters/ |
| 走势/热力维度没定死就入库 | 🔴 | §5.3 清单先于数据入库；时间/地区/类别维度在表结构设计时定死 |
| 三模块仪表盘需新增 read 端点 | 🟡 | 与「全走 /chat」共存（对话面 + 读模型面），在契约文档显式定义 |
| 供应商评分口径未定（前端算 or 后端给） | 🟡 | 待产品定义；Mock 阶段前端先自定一套，标注"待定" |
| agent 慢路径误超时 | 🟡 | 超时 ≥60s + 占位 + 停止按钮；Phase 4 硬验收 |
| 「联动操作卡」是前端自建能力 | 🟢 | 规划方案未定义后端信号；在 `price_records` 等结果上自建按钮 |
| 限流撞墙（连传多文件） | 🟢 | 上传串行 + 退避 |
| 类型/契约漂移 | 🟢 | Domain 契约 + 适配器隔离；后续 openapi-typescript 自动生成后端类型 |

**需要用户拍板（不阻塞开工）**：
1. **供应商评分口径**（前端算 vs 后端给）——Mock 阶段前端先自定。
2. 商机看板若做"进行中/已截止"状态语义，需在数据入库时带状态字段（§5.3 清单第 6 行）。
