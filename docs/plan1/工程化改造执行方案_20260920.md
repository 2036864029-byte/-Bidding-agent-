## 2. Phase 0 · 止血（当天可完成，零风险）

### P0-1 清理仓库体积 ← **最高优先级，先做这个** ✅ **已于 2026-09-20 完成**

> **订正**：本项原标题为"建立远程备份"，基于"无 upstream = 从未 push"的判断。
> 2026-09-20 复查发现该判断**有误**，实际是：
> - `origin` **是配好的**：`git@github.com:zonggao7-art/ztb_demo.git`
> - **但那是别人的仓库**（用户 2026-09-20 确认：*"远端是别人的仓库，现在不协作了，
>   这是我的个人项目先保存到本地就可以"*）→ **禁止 push**
> - 最后一次成功推送是 2026-09-01（`origin/main` 停在 08-25 的 `81a0b8d`）

真正的"止血"项是**仓库体积**：`.git` 达 **5.0 GB**，其中 **4.9 GB 是孤儿 Git LFS 数据**。

**诊断**（实测）：

| 路径 | 体积 | 性质 |
|---|---|---|
| `.git/lfs/tmp` | 2.9 G | 19 个临时文件，时间戳 **2026-09-05 08:38** —— 一次**中断的 LFS 传输**残留 |
| `.git/lfs/objects` | 2.1 G | 17 个对象 |
| `.git/objects` | 46 M | 真正的 git 数据 |

且仓库**已无 `.gitattributes`**、`git lfs ls-files` 为空 → LFS 已不跟踪任何文件。
全历史扫描（3411 个唯一对象）确认**没有任何 blob 是 LFS 指针** → 这 4.9 GB 无提交引用。

**执行（先移开 → 验证 → 再删，可回退）**：

```bash
# ① 预检：无中断的 git 操作
for f in rebase-merge rebase-apply MERGE_HEAD CHERRY_PICK_HEAD; do [ -e ".git/$f" ] && echo "!! $f"; done

# ② 记录基线
du -sh .git; git rev-list --count --all; git fsck --full

# ③ 移开（同盘改名，瞬时；保留可回退）
mv .git/lfs/tmp     .git/lfs/tmp.orphan_bak
mv .git/lfs/objects .git/lfs/objects.orphan_bak

# ④ 验证：计数一致 + fsck 干净 + 能读历史提交内容
git rev-list --count --all      # 应等于基线
git fsck --full
git show main:README.md | head -2

# ⑤ 确认无误后真删
rm -rf .git/lfs/tmp.orphan_bak .git/lfs/objects.orphan_bak
```

**实测结果**：`.git` **5.0 GB → 51 MB**；fsck 干净（仅 dangling blob，属正常垃圾）；
254 提交 / 7 refs / HEAD 不变；工作区未受影响。

**验收**：`du -sh .git` < 100 MB，且 `git fsck --full` 退出码 0。

> **教训（写进 README 的约束）**：本项目**不要引入 Git LFS**。
> GitHub 免费账户 LFS 配额仅 1 GB 存储 / 1 GB 月带宽，而本项目数据动辄数 GB
> ——这也解释了 09-05 那次推送为何失败并留下 2.9 GB 残渣。
> 大文件一律走 `.gitignore` 外置。

**备份（可选，需用户决定）**：若日后想要异地备份，需**新建自己的仓库**
（Gitee / GitHub / 自建服务器均可）。**不要**复用 `origin`。
可选加固：`git remote remove origin` 消除误推风险（需用户同意）。

## 3. Phase 1 · 测试分层（核心，Phase 2 的前置）

### 设计取向：默认 hermetic，显式 opt-in live

**不做**的事：不给 140 个文件逐个打 `@pytest.mark.unit`。
理由：机械成本高、易漏、且**方向错了** —— 正确的默认值是"隔离"，
需要真实服务的才是例外。例外应该显式声明，不该让 139 个文件为 1 个文件买单。

```
默认（无标记）      → 必须 hermetic：网络被闸门拦住，联网即失败
@pytest.mark.integration → 需要真实服务（Milvus / MySQL / 隧道 / LLM），CI 不跑
@pytest.mark.e2e         → 端到端，仅本地手工跑
@pytest.mark.golden      → 金标集门禁（已有 1 个文件在用），CI 可选跑
```

### P1-1 网络闸门（本方案最高价值的一项）

**机制已实测验证**（附录 A）：patch `socket.socket.connect` 后，
`httpx.post(...)` 与 `pymysql.connect(...)` **均被拦下**。

新建 `test/_support/hermetic.py`：

```python
"""非 live 用例的网络闸门 —— 把"静默依赖开发机状态"变成"显式失败 + 修复指引"。

为什么需要：test_no_hits_above_threshold 漏 mock embedder、
test_real_compiled_subgraph 打错过 patch 目标 —— 两个用例都在不该联网时
联了 127.0.0.1:18003，表现是"本机跑隧道就绿、不跑就红"，
而不是失败在正确的层。加了闸门后，这类问题在**第一次运行**就暴露。
"""
from __future__ import annotations

import socket

_HINT = (
    "非 hermetic 用例试图联网 {addr!r}。\n"
    "  修法 1（首选）：补 mock —— 见 test/_support/fakes.py；\n"
    "  修法 2（确需真实服务）：给该用例加 @pytest.mark.integration。"
)


class NetworkBlockedByTest(RuntimeError):
    """非 live 用例联网 —— 要么补 mock，要么显式标记。"""


class NetworkGate:
    """可安装/卸载的全局网络闸门（幂等，嵌套安全）。"""

    def __init__(self) -> None:
        self._saved: list[tuple[object, str, object]] = []

    def install(self) -> None:
        self._patch(socket.socket, "connect")
        self._patch(socket, "create_connection")

    def uninstall(self) -> None:
        for target, name, original in reversed(self._saved):
            setattr(target, name, original)
        self._saved.clear()

    def _patch(self, target: object, name: str) -> None:
        original = getattr(target, name)
        self._saved.append((target, name, original))

        def _blocked(*args, **kwargs):
            addr = args[1] if name == "connect" and len(args) > 1 else args[0]
            raise NetworkBlockedByTest(_HINT.format(addr=addr))

        setattr(target, name, _blocked)
```

**为什么手写而不引 `pytest-socket`**：`pytest-socket` 是成熟方案（`--disable-socket`
+ `@pytest.mark.enable_socket`），但它是"默认拦 + 白名单放行"的粗粒度开关，
无法对**非 127.0.0.1 的真实域名**给出"你该补哪个 mock"的定向提示。
本项目的故障形态恰恰全是环回地址（隧道 18003 / Milvus 19531 / MySQL 3306），
白名单式插件会把它们一起放行，等于拦不住。
**若坚持用成熟插件**：`uv add --dev pytest-socket` + `addopts = --disable-socket`，
用 `@pytest.mark.enable_socket` 标注 live 用例 —— 可作为 P1-1 的备选实现。

`test/conftest.py` 只做**装配**（保持实现与接线分离）：

```python
@pytest.fixture(autouse=True)
def _network_gate(request):
    """非 live 用例禁用网络。标记了 integration/e2e 的用例放行。"""
    if request.node.get_closest_marker("integration") or request.node.get_closest_marker("e2e"):
        yield
        return
    from test._support.hermetic import NetworkGate

    gate = NetworkGate()
    gate.install()
    try:
        yield
    finally:
        gate.uninstall()
```

## 4. Phase 2 · CI（4 个解耦 job）

新建 `.github/workflows/ci.yml`。
**job 解耦的收益**：失败定位清晰（哪个 job 红＝哪一类问题）、并行更快、
且**部分失败不阻塞其余**（如 lint 挂了仍能看测试结果）。

```yaml
name: CI

on:
  push:
    branches: [main, feat/**]
  pull_request:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  # ── Job 1：缺陷类静态检查（阻断）────────────────────────────
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
        with:
          enable-cache: true
      - run: uv sync --frozen --group dev
      - name: ruff —— 缺陷类（阻断）
        run: |
          uv run ruff check \
            --select F821,F822,F823,F811,F841,E741,F601,F602,F632 \
            --output-format concise
      - name: ruff —— 风格类（报告，不阻断）
        if: always()
        run: uv run ruff check --statistics || true

  # ── Job 2：hermetic 测试（阻断）──────────────────────────────
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
        with:
          enable-cache: true
      - run: uv sync --frozen --group dev
      - name: pytest（hermetic 子集 + 覆盖率）
        run: |
          uv run pytest test/ \
            -m "not integration and not e2e" \
            --cov=agent --cov=api --cov=core \
            --cov=price_engine --cov=orchestration \
            --cov-report=term-missing \
            --cov-report=xml
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: coverage
          path: coverage.xml

  # ── Job 3：契约校验（阻断，失败信息直指契约漂移）────────────
  contract:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
        with:
          enable-cache: true
      - run: uv sync --frozen --group dev
      - run: uv run pytest test/contract -v

  # ── Job 4：前端（阻断）───────────────────────────────────────
  frontend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: frontend/package-lock.json
      - run: npm ci
      - run: npm run typecheck
      - run: npm run test
```

### P3-3 E501（57 条）—— 棘轮，不强制清零

行长是风格偏好，不值得为它改 57 处代码（翻车风险 > 收益）。采用**棘轮**：
把当前条数写入基线文件，CI 断言"不增长"。

```bash
# scripts/ci/lint_ratchet.py
"""风格类告警棘轮：只允许减少，不允许增加。"""
import json, subprocess, sys
from pathlib import Path

BASELINE = Path(__file__).with_name("lint_baseline.json")

def current() -> dict[str, int]:
    out = subprocess.run(
        ["ruff", "check", "--statistics", "--output-format", "json",
         "agent", "api", "core", "price_engine", "public_kb", "orchestration"],
        capture_output=True, text=True,
    ).stdout
    return {row["code"]: row["count"] for row in json.loads(out or "[]")}

def main() -> int:
    now = current()
    base = json.loads(BASELINE.read_text()) if BASELINE.exists() else {}
    regressions = {
        code: (base.get(code, 0), n)
        for code, n in now.items()
        if code not in ("F821","F822","F823","F811","F841","E741") and n > base.get(code, 0)
    }
    if regressions:
        for code, (was, is_) in regressions.items():
            print(f"::error:: {code} 从 {was} 增至 {is_}")
        return 1
    print("棘轮通过：风格类告警未增长")
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

首次执行 `--update-baseline` 写入当前值即可。**收益**：不阻塞当前工作，
但杜绝"下一个 PR 再添 30 条"。

### P3-4 覆盖率 —— 棘轮，不设绝对阈值

绝对阈值（如"必须 80%"）对本项目有害：大量分支只在 live 环境可达（Milvus 召回 28.9%、
Redis 后端 66.3%、MinerU 解析），强行拉高会催生**为覆盖率而写的假测试**。

采用**只降不升的棘轮**：

| 项 | 值 |
|---|---|
| 当前基线（hermetic 子集跑出，P1 完成后重测） | **83%**（7674 语句 / 1284 未覆盖） |
| CI 行为 | 覆盖率低于上次记录即失败；提升则自动刷新基线 |
| 基线存放 | `test_report/coverage_baseline.json`（`test_report/` 已在 `.gitignore`，需移到 `scripts/ci/` 或改为提交） |

```python
# scripts/ci/coverage_ratchet.py
"""覆盖率棘轮：只允许上升。基线随每次提升自动刷新。"""
import json, re, sys
from pathlib import Path

BASELINE = Path(__file__).with_name("coverage_baseline.json")
TOTAL_RE = re.compile(r"^TOTAL\s+(\d+)\s+(\d+)\s+(\d+)%", re.M)


def measure(cov_report: Path) -> float:
    text = cov_report.read_text(encoding="utf-8", errors="ignore")
    match = TOTAL_RE.search(text)
    if not match:
        print("::error:: 未能从覆盖率报告解析 TOTAL 行")
        sys.exit(2)
    return float(match.group(3))


def main() -> int:
    current = measure(Path(sys.argv[1] if len(sys.argv) > 1 else "coverage_report.txt"))
    baseline = json.loads(BASELINE.read_text())["percent"] if BASELINE.exists() else 0.0
    if current + 0.01 < baseline:
        print(f"::error:: 覆盖率下降：{baseline}% → {current}%")
        return 1
    if current > baseline:
        BASELINE.write_text(json.dumps({"percent": current}, indent=2), encoding="utf-8")
        print(f"覆盖率提升：{baseline}% → {current}%，基线已刷新（记得提交）")
    else:
        print(f"覆盖率持平：{current}%")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

**关于 83% 这个数**：它是**在 hermetic 子集下**也达不到的 —— 上表基线是**全量**
（含 2 个 live 依赖用例）跑出来的。P1 完成后必须**重测 hermetic 子集的覆盖率**，
那才是 CI 实际比的数（会低于 83%，因为 semantic / redis / modules 的集成段被排除）。
**重测值才是棘轮基线**，不要直接拿 83% 去卡。

## 6. Phase 4 · 契约自动校验

### 为什么需要（本项目的真实事故）

`api/schemas.py:29` 留着一条注释：

> ⚠️ **从 `core.protocol.reply.ReplyType` 派生，不要在这里另抄一份字面量** ——
> 曾经抄了一份且漏了 `deep_agent`/`safety`，导致第 3 项上线后 agent 路由的问题
> **每个都 500**。

后端内部已经用"派生"解决了。**但前端仍是手抄**：
`frontend/src/types/chat.ts:10` 有一份独立的字面量联合
（`'kb_answer' | 'price_records' | ... | 'clarify'`，共 8 项）。后端加一个 `reply_type`，
前端不跟着改 → **静默落到 fallback 渲染分支**，不报错、不告警。

> **当前状态**：实测前端 8 项 == 后端 `get_args(ReplyType)` 8 项，**今天是一致的**。
> 这正是契约测试该有的形态 —— 现在通过，防止未来漂移。

### P4-1 后端内部契约（ReplyType ↔ OpenAPI）

新建 `test/contract/test_protocol_contract.py`：

```python
"""出口协议契约：ReplyType 是唯一真值，任何派生副本都必须与它一致。"""
from typing import get_args

from core.protocol.reply import ReplyType
from api.schemas import ChatResponse


def test_chat_response_enum_derives_from_reply_type():
    """ChatResponse.reply_type 的 JSON Schema 枚举 == ReplyType。

    回归：api/schemas.py 曾手抄一份且漏了 deep_agent/safety → 全 500。
    """
    schema = ChatResponse.model_json_schema()
    assert set(schema["properties"]["reply_type"]["enum"]) == set(get_args(ReplyType))


def test_branch_map_covers_every_reply_type():
    """branch → reply_type 的映射表必须覆盖 ReplyType 全集（无孤儿分支）。"""
    from core.protocol.reply import _BRANCH_TO_REPLY

    assert set(_BRANCH_TO_REPLY.values()) == set(get_args(ReplyType))


def test_every_capability_branch_has_reply_type():
    """注册表里每个能力，都能在 branch 映射表里找到落点。

    防的是：新增能力登记了 registry，却忘了在 _BRANCH_TO_REPLY 加一条
    → 落到 .get(branch, "fallback") 兜底，前端把"成功作答"当降级提示渲染。
    """
    from agent.registry import get_default_registry
    from core.protocol.reply import _BRANCH_TO_REPLY

    missing = [
        spec.id for spec in get_default_registry().all()
        if spec.enabled and spec.id not in _BRANCH_TO_REPLY
    ]
    assert not missing, f"能力未在 _BRANCH_TO_REPLY 登记（会静默落 fallback）：{missing}"
```

> 第三条是本方案里**唯一一条防止"未来出错"的断言** ——
> 它把"registry 登记"与"出口协议登记"两个必须同步的动作绑在一起。
> 这正是"功能解耦"的反面约束：解耦可以，但**跨模块的同步点必须有测试锚住**。

### P4-2 前后端契约（ReplyType ↔ types/chat.ts）

```python
# test/contract/test_frontend_contract.py
"""前后端契约：前端类型联合必须与后端 ReplyType 同步。

前端不做 codegen（避免引入构建期依赖），改为**断言一致性**：

from pathlib import Path
from typing import get_args

from core.protocol.reply import ReplyType

_CHAT_TS = Path(__file__).resolve().parents[2] / "frontend/src/types/chat.ts"
_UNION_RE = re.compile(r"export type ReplyType\s*=\s*(.+?);", re.S)

    assert match, f"未能在 {_CHAT_TS} 里定位 ReplyType 联合（前端类型结构变了？）"
    return set(_MEMBER_RE.findall(match.group(1)))


def test_frontend_reply_type_union_matches_backend():
    backend = set(get_args(ReplyType))
    frontend = _frontend_reply_types()
    assert frontend == backend, (
        f"前后端 reply_type 契约漂移。\n"
        f"  后端有前端无：{sorted(backend - frontend)}\n"
        f"  前端有后端无：{sorted(frontend - backend)}\n"
        f"  修法：更新 {_CHAT_TS} 的 ReplyType 联合（并补渲染分支注册表）。"
```

### P4-3 price_records 列契约（机器键 + 模板完整性）

`price_records` 的表格列由**服务端下发**（`data.columns`，`key` 是机器名）。
`a06a66e` 之前用中文列名当行键，导致前端只能靠中文字面量认字段、**静默失效**
（`price_engine/rendering/output_templates.py:300-303` 留着这条注释）。

**真实 API**（已核对）：`_FIELD_REGISTRY`（30 个 `FieldDescriptor`）是字段权威表，
`_ROUTE_TEMPLATES`（10 个模板）按 `(sub_route, query_type)` 组织，
`_apply_output_template(...)` 产出 `OutputRecords(rows, columns)`。

新建 `test/contract/test_price_columns_contract.py`：

```python
"""price_records 列契约：行键必须是机器名，且模板不得引用未注册字段。"""
import pytest

from price_engine.rendering import output_templates as ot


def test_field_registry_keys_are_machine_readable():
    """字段注册表的 key 必须是机器名（ASCII），不能是中文表头。

    回归：原实现把中文标签直接当行键写进响应 → 前端只能靠中文字面量认字段，
    后端一换标签前端就静默失效（无编译错、无测试失败）。
    """
    for key in ot._FIELD_REGISTRY:
        assert key.isascii(), f"字段 key {key!r} 非 ASCII（中文不能当机器键）"


@pytest.mark.parametrize(
    "route,qtype",
    [(r, q) for r, byq in ot._ROUTE_TEMPLATES.items() for q in byq],
)
def test_template_field_refs_exist_in_registry(route, qtype):
    """模板引用的字段必须都在注册表里 —— 否则运行时被静默跳过。

    _apply_output_template 里 `if fd is None: continue` 会无声吞掉拼错的字段名，
    列直接从响应里消失且不报错。这条断言把"静默"变成"提交即失败"。
    """
    tpl = ot._ROUTE_TEMPLATES[route][qtype]
    keys = set(tpl.required) | set(tpl.optional) | set(tpl.display_order)
    for extra in tpl.conditional.values():
        keys |= set(extra)
    missing = sorted(k for k in keys if k not in ot._FIELD_REGISTRY)
    assert not missing, f"{route}/{qtype} 引用了未注册字段：{missing}"


def test_emitted_columns_use_registry_keys():
    """实际产出的 columns[].key 必须来自注册表，且 label 与注册表一致。"""
    reg = ot._FIELD_REGISTRY
    for route, byq in ot._ROUTE_TEMPLATES.items():
        for qtype, tpl in byq.items():
            # 造一条"全字段有值"的记录，逼出最大列集
            record = {fd.source_col: f"v_{fd.key}" for fd in reg.values()}
            out = ot._apply_output_template(tpl, [record], intent=None)
            for col in out.columns:
                assert col["key"] in reg, f"{route}/{qtype}: 列 key {col['key']!r} 不在注册表"
                assert col["label"] == reg[col["key"]].label, (
                    f"{route}/{qtype}: 列 {col['key']!r} 的 label 与注册表不一致"
                )
```

**实施提示**：第三条需要造一条"全字段有值"的记录，而
`_apply_output_template` 的 `intent` 参数会影响 `conditional` 字段的活跃集 ——
参数签名以实际实现为准（`intent=None` 可能需换成最小的假 intent 对象），
实施时以**能跑通且断言有意义**为准，不要为了测试去改业务签名。

## 7. Phase 5 · 版本纪律与本地门禁

### 先回答你的问题：个人项目还需要"分支与评审"吗？

**不需要 PR 评审，但需要纪律。** 我把这一项拆成 7 条逐条判断：

| 原条目 | 个人项目 | 理由 |
|---|---|---|
| PR + 人工 review | ❌ **不要** | 没有第二个人。自己给自己 review 是形式主义，只会浪费时间 |
| 远程备份（push） | ⏸️ **暂不需要** | 用户暂不需要异地备份（个人项目，本地保存即可）。**且 `origin` 是别人的仓库，禁止 push**（详见 P0-1）。日后若要备份 → 新建自己的仓库 |
| `main` 保持绿 | ✅ 要 | 单人项目最怕"改坏了不知道回哪" |
| 短命 feature 分支 | ⚠️ 可选 | 有价值：保证 `main` 始终处于可发布状态。你现在用 `feat/eval-observability` 就是这么做的 |
| 版本 tag | ✅ **要** | 单人项目的"可回溯点"，**比 review 有用得多** |
| 提交信息规范 | ✅ 已有 | 现有 commit message 质量很高（`feat(scope): 中文说明`），保持 |
| 本地门禁 hook | ✅ **要** | **这才是 PR review 的替代品** —— 把机械检查自动化，人只留下判断 |

**一句话**：把"评审"换成"**自动化门禁 + 版本 tag**"。
评审能提供的机械价值（"你没跑测试、你引入 lint 错误、你破坏契约"）
全部可以由 Phase 1~3 的测试与门禁承担；评审能提供的判断价值需要第二个人，你没有。

建议节奏：**每个 Phase 收口打一个 tag**。出问题时 `git diff v0.9.0..HEAD` 定位比翻 log 快得多。

### P5-2 本地门禁 hook（pre-commit）

`pre-commit>=4.6.2` 已在 dev 依赖里，但**没有配置文件**（装了没用）。新建
`.pre-commit-config.yaml`，只放**秒级**检查（重活留给 CI）：

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.16.6
    hooks:
      - id: ruff
        args: [--select, "F821,F822,F823,F811,F841,E741,F601,F602,F632", --fix]
        files: ^(agent|api|core|price_engine|public_kb|orchestration)/

  - repo: local
    hooks:
      # 契约测试是秒级的，值得放本地 —— 契约漂移在提交前就该拦住
      - id: contract-tests
        name: 契约测试（前后端 reply_type / 列 key）
        entry: .venv/Scripts/python.exe -m pytest test/contract -q
        language: system
        pass_filenames: false
        files: ^(core/protocol|api/schemas|frontend/src/types)/

      # 只跑 hermetic 快速子集，全量留给 CI
      - id: fast-tests
        name: 快速单测（hermetic 子集）
        entry: .venv/Scripts/python.exe -m pytest test/core test/orchestration -q -m "not integration and not e2e"
        language: system
        pass_filenames: false
        stages: [pre-push]     # 只在 push 前跑，不拖慢每次 commit
```

**设计要点**：把慢检查放 `pre-push` 而非 `pre-commit` ——
否则每次 commit 都要等，人会开始用 `--no-verify`，门禁形同虚设。

**跨平台注意**：`entry` 里的 `.venv/Scripts/python.exe` 是 Windows 路径。
本机是 Windows 所以可用；若日后在 Linux/macOS 上开发，需改为
`language: python` + `additional_dependencies`，或退化成 `python -m pytest`（依赖 shell PATH）。
**不建议**为此引入包装脚本 —— 个人项目里这属于多余的抽象层。
