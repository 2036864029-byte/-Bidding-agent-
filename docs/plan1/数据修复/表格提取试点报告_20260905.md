# 表格提取试点报告（PaddleOCR PP-StructureV3 实证）

> 日期：2026-09-05
> 背景：用户确认三本书存在真表格（1200问 61 处表题注/27 页、白如银 11 页表关键词、全书 附表引用）。此前 find_tables 检测全误判，需验证 PaddleOCR 是否可恢复无框 OCR 表格。
> 方法：本地 Docker Desktop 拉取 PaddleOCR（paddlepaddle/paddle:3.0.0 + paddlex[ocr]==3.7.2），PP-StructureV3 管线对 5 个真实表格页推理。
> 状态：**试点完成，暂停执行**。当前无框表格三条检测路径（文本层/视觉布局/纯表格管线）均判"不是表"，但表格内容 OCR 可全读。

---

## 一、结论先行

| 检测路径 | 结果 |
|---|---|
| 文本层工具（PyMuPDF find_tables default/lines） | **失败**：矢量线=0，无表可查 |
| PyMuPDF find_tables(text) | **误判**：双栏页当表（全书 546/574），脚注缩进当表（白如银 9 页） |
| **PP-StructureV3 布局模型**（PP-DocLayout_plus-L） | **失败**：表1-1 区域被分类成 `text`（score 0.986），表格子模型未触发 |
| PP-StructureV3 裁剪表格区单独喂 | **失败**：布局门仍判 text，`table_res_list=0` |
| 纯表格管线 `table_recognition`（PP-DocLayout-L + SLANet） | **失败**：`table_res_list=0` |

**本质结论**：这些是**无框表格**（列边界仅靠留白），文本层启发式和视觉布局模型共同把它识别为"连续排版的文字"——两类工具的共同盲区，非选型错误。**表格内容 OCR 全部可读**（表1-1 的 4 列×2 行单元格文本完整），只是每行被 OCR 合并为单条文本、无网格结构。

## 二、试点环境（可复用）

- **镜像**：`paddle-paddlex:local`（本地已 commit，8.23GB），基于 `paddlepaddle/paddle:3.0.0` + `pip install "paddlex[ocr]==3.7.2"`。
- **模型缓存**：`analysis_out/table_pilot/.paddlex_cache`（容器内挂载 `/root/.paddlex`，已含 PP-StructureV3 全部模型：PP-OCRv5 det/rec、PP-DocLayout_plus-L、SLANeXt_wired、SLANet_plus、RT-DETR-L wired/wireless table cell det、PP-FormulaNet 等）。
- **容器网络坑（Windows 关键）**：
  - Docker Desktop 默认 NAT 下容器**连不上外网**（DNS 时断时续、TLS 被重置），宿主却正常。
  - 解法：**`--network host`**（共享宿主网络栈）后 pypi/阿里源均通。`--dns` 部分有效但不如 host 可靠。
  - pip 源：清华源 403、阿里源容器内 DNS 不稳，**PyPI 直连 + host 网络最稳**；本次最终用 `--network host` + 阿里源成功。
- **运行模板**：
  ```
  docker run --rm --network host \
    -v D:/agent_project/ztb_demo/analysis_out/table_pilot:/work \
    -v D:/agent_project/ztb_demo/analysis_out/table_pilot/.paddlex_cache:/root/.paddlex \
    paddle-paddlex:local bash -c "cd /work && python <脚本>.py"
  ```
- 注意：`paddlex --install` 仓库管理器路径已坏（`repo_manager/repos` 不存在）；正确装法 = `pip install "paddlex[ocr]==<版本>"`。PaddleX 3.7 的 `predict()` 返回**生成器**，须 `next(iter(...))`。

## 三、试点过程与证据（表1-1，1200问 p9）

1. **表格真实存在**：渲染图（1700×2200）目视确认 表1-1 为 4 列×2 行（首要宗旨|主体|所用资金|适用的法规、程序；行=政府采购/公共采购）。
2. **布局模型判 text**：`layout_det_res` 中表格区 bbox [166,1585,1526,1948] 标签=`text`(0.986)；`paragraph_title`=[170,1476,330,1519]（表题注）。无任何 `table` 标签候选。
3. **裁剪后仍失败**：裁出表格区 y[560:1240] 单独喂 `table_recognition` 管线，布局门依然判 text → `table_res_list=0`。
4. **OCR 内容完整但合并**：整页 OCR 读出全部单元格，但**每行 4 列被合并成一条文本**（例：y=635 行 `首要宗旨主体所用资金适用的法规、程序`，单 bbox x0=177 跨全宽）。→ 列边界在 OCR 行检测层也被合并。
5. **word box 路径受阻**：尝试 `return_word_box=True` 取逐字框做列聚类——PP-StructureV3 直接返回空；独立 `OCR` 管线撞 paddle 运行时版本不兼容（strides 报错）。**该路径需另修环境/API，属自定义开发**。
