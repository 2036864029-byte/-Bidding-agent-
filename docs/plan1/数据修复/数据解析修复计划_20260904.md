## 0. 结论先行

### 0.1 技术栈是否调整？—— 不更换，但「档位接口」现在定义、重依赖延后落地

- 不更换（同 v2）：根因都在现有代码逻辑，无选型错误；换栈代价远大于修复。
- **新增决策：PaddleOCR 不现在安装，但把「第三档路由 + Tier 2 接口」现在就设计进架构。**
  - 事实依据：《全书》是当前唯一扫描件（574 页 100% 图片页），但其**内嵌 OCR 文本层质量好**（平均 1396 字/页、法条结构完整，已抽样 90/300/500 页复核）。这本书的全部问题（页眉、页标记、双栏、第十二条被切）来自**管线逻辑，不是 OCR 错误**。现在上 PaddleOCR = 重新 OCR 一本已经 OCR 好的书，不修旧错还引入新错 + 新依赖（paddlepaddle 数百 MB、与 setuptools<70 环境需验证）。
  - 防「以后重构」的办法不是现在装包，而是**现在定义 Parser 协议 + 路由判定指标**。未来「无文本层扫描件」真实到达时，只需新增一个实现协议的 Parser 类 + 一个路由分支——加一个类，不是重构。
  - PaddleOCR 的定位：MinerU 今天已能 OCR 扫描件，「能不能处理扫描件」不存在能力缺口；PaddleOCR 是**规模化优化（本地、快、便宜），不是能力补全**。优化等规模到来 + 能用真实页验证时再做。
  - **触发信号**（写进路由指标）：出现 `img_coverage>30%` 且文本层缺失/乱码率高的页 → 启动 Tier 2 选型。当前三本书均不触发。

### 0.2 实施路线（不变）

```
Phase A（本次执行）  文本清洗链路 —— 只产出「清洗后 markdown」，不切分
Phase B（后续另行设计）文本切分链路 —— 重新设计分块方式（SemanticChunker 重设计）
Phase C（两者之后）   重建入库 —— 全量重建 Milvus（chunk_uid 全变）
```

**为什么拆**（同 v2）：v1 把清洗与切分耦合在 `handoff.chunk_markdown`（cleaner → adapt_pdf_markdown → chunker），`adapt_pdf_markdown` 同时承担「文本归一」与「分块」两类职责。既然切分确定要重设计，就应先把「文本归一」独立成纯文本阶段，让清洗产物（干净的 markdown）成为独立、可验收、可复用的资产；切分重设计时直接消费干净 markdown，互不阻塞。

**Phase A 的产出物**：清洗后 markdown（即新版 `assembled.md`——人工可读 + 后续切分输入）；**验收指标是文本级的**（丢字、乱码、页眉、标题结构、表格），不再是 chunk 指标（chunk 指标归 Phase B）。

### 0.3 v3 相对 v2 的增量（本章核心）

1. **接口前定（A0）**：三档路由接缝 + `ParserOutput` 契约。多档输出格式一致从「后处理抹平」升级为「**契约 + 单入口 + 一致性校验**」三件套——正面回答《优化方案》「统一出口后处理怎么保证」的疑问。
2. **表格方案证据化（A3-4）**：存量核实已完成（实证：三本书无矢量线表格、find_tables 全为双栏/脚注误判）→ 架构定为「**引擎注册表**」：find_tables_engine（数字 PDF 网格）+ html_engine（业务网页数据）本期实现，paddleocr_engine / column_cluster 槽位预留，PaddleOCR 安装推迟到「无文本层扫描件」到达时 pilot。
3. **保真回归装置（A5）**：黄金页对 + 文本级基线脚本**入库回归**，作为一等交付物——正面回答「几百个测试为什么没守住质量」（既有测试守的是行为，没守内容保真；保真断言从本次起成为回归的一部分）。

## 1. 架构调整

### 1.1 清洗从切分中拆出（v2 不变）

**现状**：
```
PDF → PdfRouter.parse → 原始 markdown（写 assembled.md）
    → chunk_markdown: TextCleaner.clean → adapt_pdf_markdown
        （strip_toc_noise + split_table_blocks + _split_heading_inline_articles → chunker）
    → Documents → jsonl
```
`assembled.md` 是「原始解析输出」（含页标记、乱码、页眉、短行碎片），清洗只在入库前瞬间发生，没有独立的干净文本资产。

**目标**：
```
PDF → PdfRouter.parse（抽取层修复：页眉识别/首行/双栏拼接/标题归一）
    → [新增] 文本清洗链路 clean_markdown()：
        TextCleaner（短行/LaTeX/图片/页标记/元信息）
        + 结构归一（标题行拆分/引用误读校正/列表项降级/表格生成/前置页标记）
    → 清洗后 markdown（新 assembled.md，独立可验收）
    → [Phase B] 新切分链路 chunk_cleaned_markdown() → Documents → jsonl
```

**具体改动点**（同 v2）：
- `handoff.chunk_markdown` 拆为 `clean_markdown(markdown) -> str`（Phase A）与 `chunk_cleaned_markdown(clean_md, ...) -> Documents`（Phase B）。
- `adapt_pdf_markdown` 中属于「文本归一」的部分（`strip_toc_noise`、`_split_heading_inline_articles`、列表项降级、页标记剥离、列对齐表格生成、前置页标记）**上移到清洗链路**；切分链路只保留「块怎么切、元数据怎么挂」。
- `handoff._process_single_book` 写盘内容由「原始 markdown」改为「清洗后 markdown」（`--force` 重跑一次，产出干净 assembled.md；如需调试原始输出，另存 `*.raw.md`）。

### 1.2 新增：档位路由接缝 + 输出契约（v3 增量）

```
PDF 单页
  │
  ▼
Gate 路由（pdf_router + pdf_page_profile 指标化）   ← A0-2 本期只增强诊断，不重写判定
  │
  ├─ Tier 1 fast_text（本地文本层，含《全书》OCR 层）——本期修复 A1/A2/A3
  ├─ Tier 2 PaddleOCR/PP-Structure（协议已定义，实现延后，等无文本层扫描件）
  └─ Tier 3 MinerU（现有兜底，adapter 清洗其 LaTeX/图片链接）
  │
  ▼
ParserOutput 契约（统一中间格式）                    ← A0-1 每档出口一致
  │
  ▼
clean_markdown() 单入口（A1→A2→A3 文本归一）          ← 一条代码路径 = 一种输出格式
  │
  ▼
A4 结构校验闭环（有界、文本级）                      ← 一致性证明手段
  │
  ▼
清洗后 assembled.md（独立资产）→ [Phase B] chunk → [Phase C] 重建
```

**A3-4 表格提取——引擎注册表架构（v5：存量核实修正 + PaddleOCR 试点完成）**：

**存量核实（A3-4b，已完成·修正）**：用户确认**三本书确有真表格**（1200问 61 处表题注/27 页，表1-1/1-2 + 表5-1~5-18 系列；白如银 11 页表关键词；全书 附表2-1 等引用）。此前"无真表"结论错误（只查了 find_tables 命中的少数页）。但：
- 矢量线（网格）表格页 = **0**（`find_tables(lines/default)` 三本书全 0）；
- `find_tables(text)` **全误判**：双栏页当表（全书 546/574）、脚注缩进当表（白如银 9 页）；
- **根因**：这些是无框表格（列边界仅靠留白），且 OCR 文本层把列结构压平（逐字符 15pt 等距 span）→ 文本层工具在原理上无法恢复。

**PaddleOCR PP-StructureV3 试点（A3-4c 提前做，已完成·结论负面）**：本地 Docker 起 PP-StructureV3 对 5 个真实表格页推理——
- 布局模型把表1-1 区域分类成 `text`（score 0.986），表格子模型（SLANet/RT-DETR 无线表）**未触发**；裁剪表格区单独喂纯表格管线仍判 text，`table_res_list=0`。
- **结论**：PP-StructureV3 默认管线对无框 OCR 表格同样失效（布局门盲区），但**表格内容 OCR 全可读**（每行 4 列被合并成单条文本）。详见 `docs/plan1/数据修复/表格提取试点报告_20260905.md`。
- **剩余方向待定（A 混合重建：逐字框+列聚类，1-2 天 / B 接受压平文本 / C 面向未来业务数据）**。

### A4 结构校验闭环（v3 新增，吸收《优化方案》Gate 2）

- **规则（文本级，四条）**：①标题层级（`第X章`=`#`、`第X条`=`###`、`#### （一）`→列表降级）；②标题内联正文（`第X条【…】` 后必须换行）；③引用误读（`第X条 第X款/的规定…` 且行长 >30 → 去标题标记并入前块）；④目录页（`## 目 录` 下 `….页码` 模式 → 标记 toc）。
- **机制**：单遍扫描 + 定点修复 + **最大迭代上限（3 轮）**；输出喂 A5 验收脚本。
- **与《优化方案》Gate 2 的差异**：有界（防递归死循环）；文本级（不碰 chunk）；修复点精确（不重跑整个 cleaner，避免误伤正文）。

### A5 保真回归装置（v3 新增，一等交付物）

- **为什么要做**（正面回应「几百个测试没守住质量」）：既有 564 个测试断言的是分支/形状/SQL/链路（行为正确），输入是合成页面，**从不对真实页面做内容比对**；99% 的首行删除率对一个只检查 Documents 形状的测试完全不可见。保真断言从本次起补上这一维度。

### A6 测试策略与泛化约束（v3 新增）

**主测试书：《全书》（中华人民共和国招标投标法律法规全书，唯一扫描件）。** 选它做主调参/验证书的原因：574 页中 85.5% 双栏、含高质量内嵌 OCR 文本层（扫描件路径）、页眉/页码泄漏、前置页与目录、跨页条标题被切、文本对齐型表格——**同时覆盖最多代码路径，是最复杂的一本**。拿它调参，泛化性比拿简单书调参更好；它达标是必要不充分条件。

**泛化原则（反过拟合，硬约束）**：

1. **规则必须模式驱动，禁止硬编码某本书的排版常量**。页眉识别靠"跨页重复 + 页码模式"，标题靠「第X编/章/节/条/款/项」模式，表格靠列对齐——**不得写死**"正文从 76pt 开始""白如银的书名""某页的特定 y 坐标"这类常量。原始 bug（top-12% 页眉区、<10 字全删、标题正则只认空格）正是"拿某页排版假设写规则"的产物，修复时不得重蹈。
2. **所有阈值都要有通用依据**：页眉重复 ≥2（"页眉跨页出现"是通用排版规律）、列聚类 2/3/24pt（列数/行数/列距为通用表格特征）、字号启发式（标题大于正文是通用规律）——阈值定值前说明其通用依据，不以"全书刚好通过"为准。
3. **验收口径分两层**：**主测试书《全书》达标是必要条件；另两本书（白如银/1200问）+ cleaned_v1 全量回归不倒退是充分条件**。任何规则/阈值改动，主书通过 + 泛化集不倒退才算验收通过。
4. **A5 黄金页对按通用页型抽样**，且泛化集（另两书 + cleaned_v1）各保留少量页对作为"未参与调参"的验证集，防止调参过拟合到主书。
