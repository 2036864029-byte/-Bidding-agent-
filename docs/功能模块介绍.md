## 一、这是什么

面向**政府采购与招投标**领域的 AI 助手。它把三类数据源——**法规知识库**、**结构化业务数据**、
**用户上传的文档**——接到一个能自主检索、交叉验证、并给出**可核验答案**的 agent 上。

四条核心能力：**法规知识问答**、**价格与标讯查询**、**通用对话**、**文档问答**。

**关键设计取向**：答案必须**有据可查**。法规问答带可点开的引用来源；数据查询回传的是
数据库中真实存在的记录；文档问答标明检索到哪些段落。宁可回答"检索不到"，也不臆造。

## 二、四个功能模块

### 2.1 对话控制台（`/chat`）— 主入口

自然语言提问，流式输出。它不是"一个聊天框"，而是**七个分支的统一入口**——
后端先判断问题类型，再用对应的方式回答：

| 分支 | 何时触发 | 你会看到什么 |
|---|---|---|
| **法规知识问答** | 问法规、程序、评标规则、投标流程、履约验收 | 正文 + **可点开的【来源N】引用卡片**（原件、章节、相关度） |
| **价格与标讯查询** | 问企业工商、处罚不良记录、中标记录、采购项目、项目编号 | 正文 + **结果表格**（列由服务端下发）+ 「去询价/供应商模块」联动入口 |
| **文档问答** | 上传文件后要求分析、解读、对比、提取 | 正文 + **来源段落列表**（文档/章节/片段/相关度）+ 显式兜底提示 |
| **深度综合** | **上传了文件**且问题需要**跨源比对**（如"这份标书这样约定合规吗"） | 正文 + **「思考过程」折叠面板**：规划了哪几步、每步查到什么、有哪些缺口 |
| **澄清反问** | 问题信息不足、无法消解 | 反问 + **一键候选** chips，点一下即可继续 |
| **通用对话** | 问候、问能力、闲聊 | 引导式回答 |
| **兜底引导** | 意图无法判定 | 能力引导 |

**还支持**：
- **多轮对话**：追问可以省略主语（"招标方式有哪些？" → "具体介绍一下？"），
  系统会在一次调用里完成意图分类 + 追问消解
- **文件上传**：异步解析 + 进度轮询；图片走 OCR；上传的文档只进**当前会话的私有索引**，
  不污染公共知识库
- **匿名会话 + 数据隔离**：无需登录，会话之间互不可见

### 2.2 智能询价（`/inquiry`）— 项目概况 → 报价参考

**用法**：粘贴或输入一段招标项目概况 → 语义检索历史中标公告 → 返回相似项目与金额参考。

**产出**：相似项目卡（项目名、采购人、中标供应商、中标金额、日期）+ **金额区间（万元）**
+ **查看原文**外链（可直达政府采购网原公告）+ 产品明细折叠。

**也支持**：直接上传项目文件（或从对话里带过来的上传件）作为查询输入。

### 2.3 供应商全景（`/supplier`）— 工商档案 + 中标业绩

**数据规模**：**39,969 家**企业工商库。

**用法**：按**地区 / 行业 / 关键词**筛选（服务端筛选，非前端过滤），点开看详情。

**卡片内容**：企业名称、统一社会信用代码、行业、地区、企业规模、经营状态、
**中标次数与中标金额**。

**两个如实告知的口径**（页面上会明说，不藏）：
- 一页只返回 60 家，页头显示「共 N 家，显示前 M 家」
- CCGP 新入库的约 1,058 家**没有工商字段**（无省份/行业），按地区或行业筛选时不会出现

### 2.4 商机看板（`/kanban`）— 数量口径的行业视图

**产出**：汇总指标 → 筛选行 → **行业走势（多序列，交易类型 × 月份）** → 地区热力 / 行业占比。

**为什么没有金额维度**：看板的聚合源 `trade_stat_fact` 本就没有金额指标，
现有数据只覆盖单月 8 天——画出来的金额走势只有一个点。**没有信号就不画**，
而不是凑一张好看的图。

## 三、后端能力与数据底座

### 3.1 六种处理能力

系统由一个**能力注册表**驱动：每种能力登记自己的路由特征、示例问法、所需模型槽位与工具。
新增能力只需登记一条，路由、图节点、条件边全部自动接入。

| 能力 | 底层实现 |
|---|---|
| `knowledge_qa` | RAG：Milvus 稠密 + 稀疏混合检索 → RRF 融合 → Cross-Encoder 精排 |
| `price_inquiry` | 价格引擎：5 级召回链（语义 → 全文 → LIKE → 逐词拆分 → 全表）+ SQL 生成 |
| `doc_qa` | 会话私有文档索引检索 |
| `deep_agent` | **Plan-and-Execute + Reflection**：规划 → 并发执行 → **观察回灌补检索** → 综合 → 反思 |
| `general_chat` | 通用对话 |
| `fallback` | 意图不确定时引导 |

### 3.2 价格引擎的子路由（问题会被分到哪一类）

**企业侧（`company_query`）**

| 类型 | 触发 |
|---|---|
| 企业推荐 | "推荐几个安徽省工程类的供应商" |
| 不良记录核查 | "XX公司有没有被处罚过？" |
| 企业详情 | "XX公司的注册资本是多少？" |

**标讯侧（`bidding_query`）**

| 类型 | 触发 |
|---|---|
| 中标方查询 | "XX公司中标了哪些项目？" |
| 采购方查询 | "XX医院招标过什么？" |
| 项目详情 | 给项目编号（如 `AH2024-001`）或问"这个项目谁中了" |
| 采购需求 | "我要采购120台摄像头" → 找历史相似项目的中标价 |
| 聚合统计 | "中标金额最大的项目是哪个？" |

**企业名称归一化**：支持简称与字号族（"中国移动" → 命中其全部省级子公司；
"杭州海康威视" → 命中"海康威视"字号族）。

### 3.3 数据底座

| 数据源 | 内容 |
|---|---|
| MySQL `ztb_clean` | 清洗后的结构化业务数据（中标项目、企业、处罚、产品） |
| MySQL `bidding` | 统一宽表：项目 18,497 / 企业 39,969 / 中标记录 12,209 / 公告 802 |
| Milvus `public_kb_chunked_v2` | 权威法规 PDF 分块向量（标题感知分块 + 层级结构保留） |
| Milvus `project_announcement_semantic` | 802 条中标公告语义索引（项目名 + 产品清单 + 正文） |

## 四、典型使用场景

| 你想做的事 | 怎么问 / 去哪 |
|---|---|
| 搞清一条法规怎么规定的 | 对话里直接问，点开【来源N】看原文 |
| 摸清一家公司的底 | 对话问"XX公司有没有不良记录 / 中标过什么"，或去**供应商全景** |
| 判断一份标书是否合规 | **上传标书** → 问"这样约定符合招标投标法吗" → 深度综合会拆成"读文件 + 查法规"并交叉比对 |
| 给采购需求估个价 | 对话问"我要采购120台摄像头"，或去**智能询价**贴项目概况 |
| 找几家候选供应商 | 对话问"推荐几家安徽的工程类供应商" |
| 看行业整体情况 | **商机看板** |

## 五、边界与口径（诚实说明）

1. **检索不到就直说**。法规问答有相关度下限，不足时明确提示"未检索到"，
   不生成看似合理实则无据的条文。
2. **数据有时间与地域边界**。收录范围取决于采集，回答中会标注数据来源表；
   未收录不代表现实中不存在。
3. **工商字段有缺口**。CCGP 侧新入库企业暂无工商信息，卡片会标注"暂无工商信息"。
4. **金额口径不混用**。询价模块金额统一**万元**；对话表格中标金额为**元**，
   列头会写明单位。
5. **匿名会话**。无需登录；会话之间数据隔离，上传文件不进入公共知识库。
