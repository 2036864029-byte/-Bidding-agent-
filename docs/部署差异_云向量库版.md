## 0. 一句话

**服务器上不再需要 Milvus 三件套（standalone + etcd + MinIO）**，也就没有 460 MB 向量卷要传。

实测数据（`public_kb_chunked_v2`，云端 vs 本地）：

| 项 | 本地 Milvus 2.6.23 | Zilliz Cloud（兼容 Milvus 3.0） |
|---|---|---|
| 行数 | 14,216 | **14,216** |
| BM25 top5 重合（5 条真实查询） | — | **5/5 全一致** |
| 稠密检索 | — | `cos=1.0000`，命中同一条 |
| **混合检索**（dense + sparse + `RRFRanker`） | 支持 | **支持**，5 条结果 / 94 ms |
| dense 索引类型 | HNSW（M=16/efConstruction=128） | AUTOINDEX（云上**也支持** HNSW / IVF_FLAT，实测三种都能建） |
| 单次检索延迟 | 7–26 ms | 34–56 ms |

另一个集合 `project_announcement_semantic`（802 行）同样已迁，稠密 top1 精确命中。

## 1. `.env` 必须加的三行

在服务器 `~/ztb_demo/.env` 里（值从本地 `.env.cloud` 复制，**不要把 token 写进任何会入库的文件**）：

```ini
# 向量库走云托管
VECTOR_BACKEND=cloud
MILVUS_URI=https://in03-0399fcc7472a672.serverless.ali-cn-hangzhou.cloud.zilliz.com.cn
MILVUS_TOKEN=<API Key>

# 与云端集合一致，否则检索的是另一个（空）集合
MILVUS_COLLECTION=public_kb_chunked_v2
ENABLE_MILVUS_BM25=true
```

说明：

- `MILVUS_URI` 非空时**优先于** `MILVUS_HOST`/`MILVUS_PORT`（`Settings.resolved_milvus_uri` 的实现），所以
  `deploy/api/docker-compose.yml` 里那行 `MILVUS_HOST: host.docker.internal` **不用改**，会被 URI 覆盖。
- 本地开发完全不受影响：本地 `.env` 不写 `MILVUS_URI`/`VECTOR_BACKEND`，仍连 `127.0.0.1:19531`。

## 3. 内存账：2C4G 现在站得住了

| 组件 | 自建 Milvus | 云向量库 |

| Milvus + etcd + MinIO | 1.5–2.5 GB | **0**（api 进程里一个 HTTP 客户端，30–80 MB） |
| MySQL | 0.9–1.1 GB | 0.9–1.1 GB |
| Redis + PG | 0.06–0.13 GB | 0.06–0.13 GB |
| api | 0.4–0.8 GB | 0.4–0.8 GB |
| 系统 + nginx | 0.35–0.45 GB | 0.35–0.45 GB |

对应地，`docs/资源实测方案_2C4G.md` 里的**阶段 1（起 Milvus 三件套）整段作废**，实测只剩
MySQL + api 两段，约 30 分钟就能出结论。

## 4. 验收（比手册 §6 多两条）

```bash
# ① 云端两个集合的行数必须与本地一致：14216 / 802
python - <<'EOF'
import os, pymilvus
from dotenv import load_dotenv
load_dotenv(".env")
c = pymilvus.MilvusClient(uri=os.environ["MILVUS_URI"], token=os.environ["MILVUS_TOKEN"])
for n in ("public_kb_chunked_v2", "project_announcement_semantic"):
    print(n, c.get_collection_stats(n)["row_count"])
EOF

# ② 容器能出网到云端 443（连不上时表现为启动很慢 + 检索空结果）
docker exec ztb-api python -c "import socket;socket.create_connection(('in03-0399fcc7472a672.serverless.ali-cn-hangzhou.cloud.zilliz.com.cn',443),10);print('ok')"

# ③ 启动日志必须出现这一行（确认连的是云、索引是 AUTOINDEX）
#    向量后端=cloud | uri=https://in03-... | dense_index=AUTOINDEX | bm25=True
```

手工验收沿用手册 §6：知识问答要带【来源N】、询价要返回 `price_records` 而不是空结果。

## 5. 两个容易忽略的点

1. **官网凭据用只读角色**。项目里存在重建/清空集合的接口，指到云端就是一次不可逆的清库。
   在 Zilliz 控制台给服务器单独建一个只读 API Key，写权限的 key 只留在你本机。
2. **免费额度 250 万 vCU/月** 按检索次数扣。上线前先在控制台用量面板看一次消耗速率，
   反推「每月能撑多少次问答」——这是免费版唯一可能先撞到的墙（容量 5 GB 目前只用了不到 1 GB）。
