### 2.1 商机看板：省份图点击失效 —— 已修（真 bug）

- **现象**：点任意省份（含河北）无反应，用户以为"是静态图片"。
- **根因**：画在省面**之后**的 3 个铺满画布的装饰 `<rect>`（wash/grid/veil）默认 `pointer-events: visiblePainted`，把整个地图的点击全吃掉了。
- **修复**：`ChinaMapHeatmap.tsx` 给这 3 个 rect 加 `pointerEvents="none"`；前 5 名标注框包一层 `<g pointer-events="none">`；补结构性测试（所有 `svg > rect` 必须 `pointer-events:none`）。
- **验证**：CDP 真实鼠标事件（`Input.dispatchMouseEvent`，不是 `dispatchEvent`），河北/四川/新疆/广东全部弹卡并通过。脚本 `frontend/.shots/cdp_verify_real_click.py`（gitignore）。
- **教训**：`path.dispatchEvent(new MouseEvent('click'))` 绕过命中检测；jsdom 也没有命中检测。**交互验证必须走真实鼠标事件**。

## 4. 待办 / 待决策

### 4.1 部署输入（三个问题已答）

1. **服务器规格**：2 核 4G / 80G 盘。80G 够（镜像 5–6G + MySQL 1.2G + Milvus 卷 0.5G），
   **内存是唯一硬约束**，且已决定「先实测再定升降配」——方法见 `docs/资源实测方案_2C4G.md`，
   **不要提前改瘦身版 compose**（否则测的是改后的配置，不是真实需求）
2. **域名与备案**：`openagent-lab.top` **已备案**；同主体子域名无需单独备案（以百度云接入要求为准）
3. **80/443 占用**：**不是二选一**。nginx 单进程按 `server_name` / `location` 分流，
   只要现站是 nginx 托管，新增 `conf.d/ztb.conf` 再 reload 即可共存 —— 不停机、不改原配置

**已定形态：子域名 `ztb.openagent-lab.top`，不是 `openagent-lab.top/ztb` 子路径。**

理由（别再翻案）：子路径要求改 `vite base` + `BrowserRouter basename` + `VITE_API_BASE`，
且必须改动现站 nginx 配置；更关键的是它**前提是主站与本品在同一台 nginx 上**，
而现站托管位置尚未确认。子域名在任何情况下都能落地，且仓库配置（`deploy/web/nginx.conf`）
本来就是按它写的，零改动。

**个人网站入口 = 一行链接**：

```html
<a href="https://ztb.openagent-lab.top/" target="_blank" rel="noopener">体验「招投标智能助手」→</a>
```

不要 iframe 嵌入（SSE 流式 + 键盘交互 + 移动端适配会全部劣化，且常被 CSP / X-Frame-Options 拦）。

**仍需上服务器确认的三条**（决定是「零成本共存」还是「多一步改别人的配置」）：

```bash
sudo ss -lntp | grep -E ':(80|443)\s'                    # 谁在监听（期望看到 nginx）
nginx -T 2>/dev/null | grep -nE '^\s*(server_name|listen|root)\b'
sudo certbot certificates | grep -E 'Certificate Name|Domains|Expiry'   # 证书是否通配
```

读法：输出里是 `nginx` → 直接共存；是 `caddy`/`docker-proxy`/`apache` → 多一步；
什么都没有 → 现站可能挂在别的机器或 OSS+CDN 上，`ztb` 子域仍在本机起 nginx（方案不变），
但 DNS 的 A 记录不要指向 CDN。

### 4.2 已确定的部署架构（三个输入已就位，可直接执行）

```
公网 → nginx:443 ── /      → /var/www/ztb（前端 dist 静态）
                 └─ /api/*  → 127.0.0.1:8000（api 容器）
api 容器 → MySQL:3306 / Milvus:19531 / Redis:6380 / 公网 DeepSeek+SiliconFlow+MinerU
feishu 容器 → 出站长连接（无入站端口）
```

**内存账（最大风险）**：Milvus 1.5–2.5G + MySQL 0.4–0.6G + api 0.4–0.8G + Redis + PG + nginx ≈ **3.2–4.2 GB**，
而 4G 机器的 `MemTotal` 实测约 3.7–3.9 GB —— 也就是说**理论上就贴着上限**，没有任何缓冲。

⚠️ 这里的 3.2–4.2 GB 是**估算**，不能作为升配依据（估算区间跨了 1 GB，恰好横跨「够」与「不够」）。
**先用 `deploy/ops/mem_probe.py` 实测 `MemAvailable` 低点与容器重启计数，再决定升配或瘦身** ——
完整方法、阈值表和报告模板见 **`docs/资源实测方案_2C4G.md`**。

提前拍板的两个后果都要避免：直接升配多花钱；直接上瘦身版则一旦出问题，
排查的是「我改的哪一项」而不是「容量够不够」，变量翻倍。
